# 数据源适配器：a-stock-data 交叉核对

目标：把公开 A 股日线变成**可追溯、可复核**的输入，再交给现有
`research/make_price_set.py` 和 `scripts/publish_price_set.sh`。本目录不访问
SQLite 账本、不决定下单数量、不自动发布 `reviewed` 数据。

## 1. 它解决什么问题

V2 的价格集合只接受“收盘价 + 明确来源 + 明确日期”。直接拿一个行情接口填数字，
会漏掉已知的坑：

| 已知问题 | 本适配器如何处理 |
| --- | --- |
| 腾讯成交量按“手”，科创板按“股” | 统一折算成股后再核对 |
| 最近交易日按整手取整 | 允许两者相差最多 100 股，超过即拒绝 |
| 腾讯前复权可能包含未来信息 | 只取**不复权**日线，复权口径不混入 |
| 北交所老代码返回僵尸报价 | 本批只接受沪深明确后缀；北交所不在首批范围 |
| 停牌/无成交 | 零成交量直接拒绝，不补价、不插值 |
| 单源接口坏了但返回空表 | 空序列、缺市场、包残缺都明确报错 |
| 指数混入个股价格 | 只保留沪深普通股票代码段；指数不进价格集合 |
| 东财限流 | 首批只用腾讯 + 通达信官网，不依赖东财 |

## 2. 数据来源与许可

取数实现参考并抽取自
[simonlin1212/a-stock-data](https://github.com/simonlin1212/a-stock-data)
`v3.10.4`，提交 `f21534946c42be3ad048ac938eecb1bad84cb8ab`，许可证
Apache-2.0。保留来源说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

首批实际使用两个独立收盘价来源，另用新浪复权因子做公司行为复核：

- 腾讯日 K 线（不复权）：单只标的、指定日期区间；
- 通达信官网盘后包：每个交易日全市场沪深日线，含成交额。
- 新浪 qfq/hfq 因子：只读取因子序列判断疑似除权除息/拆并股，不把复权价
  写入 CSV。

两个来源必须同时满足：同一交易日、收盘价到“分”完全一致、成交量均为正、
成交量差异不超过一手（100 股）。否则整批失败，不生成半份 CSV。

## 3. 使用方式

从 `v2/` 目录执行：

```bash
python data_sources/a_stock_data.py fetch \
  --symbols 600000.SH \
  --days 2026-10-30,2026-11-02,2026-11-03,2026-11-04,2026-11-05 \
  --out ../work/prices.csv \
  --report ../work/prices.report.json
```

- `--symbols`：必须写 `.SH` / `.SZ` 后缀，逗号分隔；
- `--days`：显式列出交易日，必须升序、不能重复；脚本不会猜节假日；
- `--out`：标准化 CSV；
- `--report`：审计 JSON，记录两个来源的原始摘要、逐日核对结果和错误；
- 退出码：`0` 可取数且审核清单无异常；`1` 取数/核对失败；`2` 参数或格式
  错误；`4` CSV 已生成，但审核清单仍有项目需要人工确认；
- **失败时不写 CSV**；`4` 时 CSV 会写出，但报告明确标记
  `status=needs_review`、`review_complete=false`。

生成的 CSV 列与现有流程完全一致：

```
symbol,day,price,source,observed_at
600000.SH,2026-11-05,9.87,tencent-tdx-crosscheck,2026-11-05T15:00:00+08:00
```

`observed_at` 是规范化的收盘时刻，不是实际抓取时间；CLI 会另在审计报告写入
`generated_at`，并记录 `expected_rows`、`rows`、`partial_rows`。失败时
`csv_sha256` 必须为空，避免把部分成功误读成完整文件。

报告还会附带 `review_findings`：当前会标出窗口内（含窗口首日相对前一日）
复权因子变化（疑似除权除息/拆并股）、复权因子缺失或覆盖不足、成交量异常等。
它只提示人工核对，**不会**自动改价或自动把批次升级为 `reviewed`。

### 3.1 一条命令取数并发布

若审核已经完成、确认该窗口可发布，可用包装脚本：

```bash
bash scripts/fetch_and_publish_reviewed.sh \
  --symbols 600000.SH \
  --days 2026-11-04,2026-11-05 \
  --set-id cn-close-20261111 \
  --pack cn-offline-fixture-pack-1 \
  --review
```

- `--review` 是明确的人工确认，缺少它时脚本拒绝发布 `reviewed`；
- 任取数/核对失败或审核清单仍有项目时，脚本不会安装价格集合；
- 审核报告与 CSV 会保存在 `OUT_DIR/audit/<set-id>.{report.json,csv}`，便于
  发布后追溯；`audit/` 子目录不会被 Rust 当作价格集合扫描；
- 目标文件已存在时仍由 `publish_price_set.sh` 拒绝覆盖，修订请换新
  `--set-id`。

## 4. 接入价格集合

先按现有指南审核来源、覆盖区间、复权口径和停牌处理，再决定信任级别。
建议第一次先用 `synthetic` 跑通链路：

```bash
python research/make_price_set.py \
  --input ../work/prices.csv \
  --out ../work/cn-close-check.json \
  --report ../work/cn-close-check.report.json \
  --set-id cn-close-check \
  --pack cn-offline-fixture-pack-1 \
  --trust synthetic \
  --coverage-start 2026-10-30 \
  --coverage-end 2026-11-05 \
  --symbols 600000.SH \
  --days 2026-10-30,2026-11-02,2026-11-03,2026-11-04,2026-11-05
```

确认缺口为 0 后，再用新的 `price_set_id` 发布到
`ASTOCK_PRICE_SETS_DIR` 指向的目录；服务启动时只加载 `reviewed` 集合。
**交叉核对通过不等于自动获得 `reviewed` 资格**：仍需人工确认样本、除权日、
停牌与数据供应商口径。单源数据或未经复核的输出只能是 `synthetic`。

## 5. 复权与公司行为

本批只输出**不复权收盘价**。V2 当前没有公司行为处理，因此：

- 请求日期内遇到除权除息、拆并股、长期停牌或身份变化，应拒绝发布该窗口；
- 不要把腾讯 `qfq`（前复权）序列直接当历史收盘价；
- 不要用同一条前复权序列同时研究历史和计算当前估值；
- 需要长历史时，先单独审核复权因子与公司行为，再新增版本化数据包。

适配器不会自行判断“某天是不是除权日”。它用两个来源核对收盘价/成交量，并
用新浪因子提示窗口内或窗口首日的因子跳变；人工审核仍需按价格集合 README
的清单逐项确认。

## 6. 离线测试

```bash
python -m unittest discover -s data_sources -p 'test_*.py' -v
```

测试全部使用本地构造的腾讯 JSON 和通达信二进制包，不访问网络。覆盖：

- 代码必须带交易所后缀，跨市场后缀拒绝；
- 日期重复、乱序、空列表拒绝；
- 腾讯复权键混入、越界日期、非有限数值拒绝；
- 通达信缺市场、截断包、NaN、市场记录过少拒绝；
- 指数行不被当作股票；
- 收盘价不一致、零成交量、成交量差异过大时整批失败；
- 成功时 CSV 列、价格、来源和报告摘要稳定。

## 7. 首批边界

| 项目 | 当前 |
| --- | --- |
| 市场 | 沪深普通股票（主板、创业板、科创板代码段） |
| 北交所 | 首批不支持；腾讯 K 线也不支持，需单独审核盘后包路径 |
| 基金/债券/指数 | 不进入 V2 股票价格集合 |
| 来源数 | 2 个收盘价来源（腾讯 + 通达信）+ 新浪复权因子复核 |
| 自动发布 `reviewed` | 不提供；必须人工审核 |
| 网络访问 | 仅手动运行 CLI；Rust 服务不联网 |
