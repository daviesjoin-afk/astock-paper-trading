# ADR 015：影子信号差异报告

状态：已实现。只读投影：比较两个实验的已存信号，回答“候选到底改了什么”，与策略版本 id、数量、成交金额无关；控制台可直接查看。

## 问题

影子候选能跑实验后，最直接的问题是：候选与基准的信号是否只在预期处不同？如果无法逐条对照，就无法判断候选行为是否符合参数变化。

## 决定

`GET /v2/signal-diff?base_cycle=&candidate_cycle=`

信号指纹（与版本无关）：

```
{ decision_at, quote_ref{pack, source, quote_id}, symbol, side }
```

- 两侧各自统计指纹的多重集合；
- `matched` = 交集计数；
- `base_only[]` / `candidate_only[]` = 各自剩余（保留重复次数）；
- 输出 `base_runs / candidate_runs` 与 canonical `digest`。

不比较：signal_id（内含策略版本）、数量、价格、成交结果。订单结果由各自实验账本负责。

## 边界

- 只读：不修改任何实验、不写账本；
- 两侧实验可以来自任意工件（审核或影子）；
- 缺失实验 → 404；
- 报告只描述信号集合差异，不构成绩效或晋级依据。

## 验收（本轮）

1. 基准 2 条、候选 1 条（`lookback=3`）→ `matched=1`、`base_only=1`（买入）、`candidate_only=0`；
2. 相同实验对比 → `matched=runs`、两侧为空；
3. 缺失实验 → 404；
4. 同一输入重复请求结果与 digest 一致；
5. 冒烟端到端覆盖基准 + 候选 + 差异。

## 未决问题

- 是否需要“按序对齐”视图（当前是集合语义，重复信号按次数计）；
- 差异报告的持久化/展示（当前按需计算，不落库）；
- 与绩效指标的关系：差异只解释行为，不解释好坏。
