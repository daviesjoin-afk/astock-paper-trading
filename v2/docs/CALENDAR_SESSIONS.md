# 固定交易日历与精确时段策略

只建设“日期/时段是否允许模拟执行 → Store 原子记录 → 固定输入回放”。
报价仍为 offline_fixture；有公开日历不等于报价已认证，也不等于收益模型达到市场精度。

## 唯一事实与依赖

新增 `domain/calendar.rs`，唯一职责是解释固定市场日历中某天是否计划开市。
消费者为 execution；只依赖 contract、chrono、serde、标准库，不读运行时时钟、网络或文件。
JSON 由 include_str 在编译时固定；不是运行时查询“最新日历”。

时段策略仍在现有 execution，Store 是唯一写入者。HTTP 不判断交易规则，
Python 仍只提供信号与报价引用，TypeScript 不新增撮合逻辑。
不新增 crate、依赖、进程、trait 框架或转发模块。

## 日历来源与适用范围

固定数据：`data/calendar-2026-v1.json`，版本 `sse-szse-scheduled-2026-v1`。
适用于现有 V2 的 SH/SZ A 股年度计划，覆盖 **2026-01-01 至 2026-12-31**。
2026-11-04 核对以下公开通知，保存发布者、文号、发布日期和 URL：

- [上交所年度安排](https://www.sse.com.cn/disclosure/announcement/general/c/c_20251222_10802507.shtml)，上证公告〔2025〕45号，2025-12-22。
- [深交所年度安排](https://www.szse.cn/disclosure/notice/t20251222_618087.html)，深证会〔2025〕481号，2025-12-22；直连有时超时，本次通过官方页面的可检索完整内容交叉核对。

只提取七段已公告休市日期，不复制整篇公告。周六、周日始终休市，政府调休工作周末
也不因此成为交易日。覆盖范围内其余周一至周五视为**计划交易日**；范围外为未知日期，保守拒绝。
不推断 2027 年安排；不声称年度计划能发现临时全市场停市、个股停牌或异常事件。

## 版本化时段政策

固定数据：`data/session-policy-v1.json`，版本 `cn-a-share-continuous-only-v1`。
来源为 [上交所2026交易规则2.4.2](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml)
与 [深交所2026交易规则2.3.2](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)。
2026 版自 2026-07-06 施行，不能用其发布时间替代生效日期。
此前日期的 A 股竞价时段依据
[上交所2023版2.4.2](https://www.sse.com.cn/lawandrules/sselawsrules2025/repeal/rules/c/c_20250612_10824490.shtml)
及 [深交所2023版2.3.2](https://docs.static.szse.cn/www/lawrules/rule/allrules/bussiness/W020230217564423808793.pdf)；
这两版对应的开盘/连续/收盘竞价时段一致。本说明只补齐 A 股时段的历史来源，
不声称整套 2026 交易规则适用于上半年，也不扩展至基金或盘后交易。
生效日参见 [上交所发布通知](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)。
不修改已固定的 session-policy-v1 JSON、版本或任何账本快照。
下列端点是本系统明确固定的模拟策略，不是完整交易所订单匹配模型。所有时间均 `+08:00`，
用完整 NaiveTime 比较，保留秒、毫秒及更细精度。

| 阶段 | 范围 | 模拟行为 |
| --- | --- | --- |
| 开盘集合竞价 | [09:15:00,09:25:00] | 未实现，拒绝 |
| 开盘前间隔 | (09:25:00,09:30:00) | 拒绝 |
| 上午连续竞价 | [09:30:00,11:30:00] | 继续现有执行规则 |
| 午间休市 | (11:30:00,13:00:00) | 拒绝 |
| 下午连续竞价 | [13:00:00,14:57:00) | 继续现有执行规则 |
| 收盘集合竞价 | [14:57:00,15:00:00] | 未实现，拒绝 |
| 其余时间/盘后阶段 | 上述范围外 | 本政策未实现，拒绝 |

因此 11:30:00 可用，11:30:00.001 不可用；14:57:00 起不模拟连续成交；
15:00:00 仍属于未实现的收盘竞价，15:00:00.001、15:00:59 也不可用。
日期门禁与行情新鲜度、T+1、现金/整手规则共同约束执行，不由 API 复制判断。

## 持久化与回放

Store 使用现有 `v2_meta` 保存日历和时段的**完整 JSON 快照**，每条 run 保存
`calendar_version` / `session_policy_version`，与请求、证据、结果和成交同事务提交。
正常、拒绝、重复记录都固定相同上下文。没有普通 API 修改这些快照或版本。

提交与回放读取保存的快照并验证已支持版本、内容与 run 引用；篡改或版本不匹配直接失败，
不加载外部资料重新解释旧成交。更新资料或交易规则必须使用新版本，不原地修改已固定版本。
当前只支持本批版本；后续二进制不支持旧版本时保守拒绝，需保留相应版本程序进行旧账本回放，
本批不建设多版本迁移框架。

当前执行规则 `v2-paper-policy-6` / SQLite schema 5 需要全新 V2 文件（日历/时段快照版本未变），例如：

```bash
cd v2
ASTOCK_V2_DB=./v2-calendar-paper.sqlite3 cargo run --locked
```

旧文件或损坏的市场快照在 WAL/DDL 初始化之前拒绝，不自动迁移、不改写历史。
测试覆盖真实磁盘拒绝不变、交易日/周末/休市/未知、精确端点/竞价、重复、事务回滚、
重开、上下文篡改与确定性回放；HTTP 链按时间递增验证，避免既有历史乱序门禁干扰。

本批不实现完整订单生命周期、流动性/部分成交、多账户、AI 晋级、临时停市、盘后交易或供应商认证。
这些限制保留；CI 成功仅证明本批代码与固定资料下的行为。
