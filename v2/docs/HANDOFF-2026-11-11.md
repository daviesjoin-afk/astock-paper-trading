## 2. 产品规则

### 2.1 单账户、单本金

- 页面只要求输入一次本金，范围是 **100 元到 10 亿元**，以“分”为最小单位；
- 系统只创建一个账户，固定 ID 为 `paper-account`；
- 初始资金严格各 50% 分给“稳健”和“激进”；
- 不存在第二个实验、账户选择器、手动权重输入或策略比较入口。

### 2.2 两个策略

| 策略 | 买入条件 | 单票上限 | 现金底线 | 最多持仓 |
| --- | --- | --- | --- | --- |
| 稳健 | 20 日均线高于 60 日均线，且 20 日波动率低于历史 60 日中位数 | 新建仓目标为槽权益的 15% | 槽权益的 10% | 3 只 |
| 激进 | 5 日动量为正，且收盘价突破前 20 日最高价 | 新建仓目标为槽权益的 30% | 槽权益的 5% | 3 只 |

白话解释：

- **均线**：一段时间的平均收盘价，用来判断趋势方向；
- **波动率**：价格上下摆动的幅度，数值越低通常越“稳”；
- **动量**：最近几天涨得快不快；
- **突破**：今天的价格超过过去一段时间的最高点。

两个策略只在“买什么”和仓位上限上不同；成交价、费用、T+1 和整手规则完全相同。

这里的 15% / 30% 是**新建仓的目标金额**，不是“持仓市值永远不得超过”的硬闸门。股价上涨会让已有持仓自然超过该比例，系统不会因此强制卖出。

现金底线是在“下单前”检查：可用现金不能低于该底线，因此费用和随后股价波动可能让结算后的现金略低于底线。它是下单闸门，不是事后强制回补。

费用口径（写死，不读券商配置）：买入佣金为成交额的万分之三、最低 5 元；卖出佣金相同，另收成交额万分之五印花税。没有过户费、滑点或最低五元之外的其他费用。这个模型是演示假设，不是对真实费率的承诺。

### 2.3 自进化调仓

这里说的“自进化”不是机器学习，也不是让程序自己改策略，而是**按两个策略最近的相对表现，在硬边界内调整它们可用的现金预算**。

每个完整交易日结算后：

1. 分别计算两个策略从上次调仓以来的收益和最大回撤；
2. 评分 = 收益率（bps）− 最大回撤（bps）；
3. 评分差距不足 100 bps（1 个百分点）时不动，避免每天微调；
4. 一次最多移动 10 个百分点；
5. 任一策略权重始终保持在 20%–80%，两者合计 100%；
6. 至少要有 2 个完整交易日才评估。

白话解释：

- **bps（基点）**：万分之一。100 bps 就是 1%；
- **回撤**：从阶段最高点跌下来的幅度；评分里减去它，相当于给“赚得多但波动很大”的策略扣分。

重要限制：

- 调仓只划转“可用现金”，**不会卖出或转移已经持有的股票**；
- 来源策略现金不足时，本次不调仓，但当天交易照常完成；
- 页面上的“权重”是预算参数，不是账户真实资产占比；
- 没有调仓记录不等于出错；样本不足、评分接近或现金不足都会保持不动。

## 4. 数据流

### 4.1 总流程

```text
公开行情（腾讯 + 通达信 + 新浪因子）
        |
        v
离线适配器：逐日核对价格和成交量
        |
        v
审计报告 + 标准 CSV
        |
        v
人工确认（除权、停牌、覆盖区间）
        |
        v
reviewed 价格集合 JSON
        |
        v
Rust 服务只读加载 -> 生成信号 -> 按收盘价模拟成交 -> 写 SQLite
```

关键点：**Rust 服务不联网**。它只读本地已发布的价格集合，因此服务器没有行情供应商依赖，也不会在盘中偷偷取价。

如果 `price-sets` 目录里同时放了多个 JSON，服务按“覆盖结束日最新、起始日更新、`price_set_id` 较大”排序，只加载排第一的集合。不要靠复制多份集合来做 A/B 测试；需要换数据时，用新的目录或替换为唯一一份已审核集合。

### 4.2 价格集合是什么

一个价格集合是一个 JSON 文件，声明：

- `price_set_id`：这批数据的唯一名字；
- `market_data_pack_id`：数据包名；
- `trust`：必须是 `reviewed`（生产）或 `synthetic`（仅隔离测试）；
- `coverage_start` / `coverage_end`：覆盖的首尾交易日；
- `entries`：每只股票每个交易日的收盘价（整数分）、来源和观察时间；
- `source_digest`：64 位十六进制摘要，用于核对内容没有被换过。

它是“完整矩形”：声明的每只股票，在集合内每个交易日都必须有一条价格。缺任何一格，整批拒绝，不会把缺失当成“停牌持有”。

### 4.3 为什么必须交叉核对

单一免费接口常见问题包括：

- 成交量单位有的是“手”，有的是“股”；
- 前复权序列会把未来信息带进历史；
- 停牌日返回 0 或空值；
- 指数、基金混进个股列表；
- 接口限流时返回空表而不是报错。

适配器用两个独立来源核对收盘价（精确到分）和成交量（允许一手差异），再用新浪复权因子提示疑似除权除息。任何一项不通过，整批失败，不写半份 CSV。

### 4.4 取数与发布

在 `v2/` 目录下，先取数并生成审计报告：

```bash
python data_sources/a_stock_data.py fetch \
  --symbols 600000.SH,600036.SH \
  --days 2026-11-03,2026-11-04,2026-11-05 \
  --out ../work/prices.csv \
  --report ../work/prices.report.json
```

退出码含义：

| 退出码 | 含义 | 能不能发布 |
| --- | --- | --- |
| 0 | 取数成功，审核清单无异常 | 可以进入人工确认 |
| 1 | 取数或核对失败 | 不能，CSV 不会写出 |
| 2 | 参数或格式错误 | 不能 |
| 4 | CSV 已写出，但审核清单仍需人工确认 | 不能直接发布 |

人工确认后，用一条命令生成并安装 reviewed 集合：

```bash
bash scripts/fetch_and_publish_reviewed.sh \
  --symbols 600000.SH,600036.SH \
  --days 2026-11-03,2026-11-04,2026-11-05 \
  --set-id cn-close-20261105 \
  --pack cn-a-share \
  --review
```

`--review` 是明确的人工确认，不是自动升级。脚本还会把 CSV、审计报告和确认记录放到 `audit/` 子目录；Rust 不会把 `audit/` 当价格集合扫描。

### 4.5 数据源上游

适配器参考 `simonlin1212/a-stock-data`：

- 版本：`3.10.4`
- 提交：`f21534946c42be3ad048ac938eecb1bad84cb8ab`
- 许可证：Apache-2.0
- 来源说明：`v2/data_sources/THIRD_PARTY_NOTICES.md`

当前首批边界：

### 5.2 端口为什么是 8600 和 18765

- `8600` 是用户和浏览器访问的公开入口，由 nginx 提供静态页面并反向代理 `/v2/`；
- `18765` 是 Rust 内核的本机端口，只允许服务器内部访问；
- 本地开发默认仍是 `8765`，这是代码默认值，不代表服务器；
- 浏览器测试使用 `18766`（内核）和 `4173`（页面预览），都是隔离端口；静态冒烟另用 `18781`，只绑定本机。

不要把这些端口混用。尤其不要把 `8765` 当成生产端口，也不要把 `18765` 直接暴露到公网。

### 5.3 首次安装或重新发布

在目标机仓库的 `v2/` 目录：

```bash
cargo build --release --locked
cd web
npm ci --no-audit --no-fund
npm run build
cd ..
sudo bash deploy/install.sh
```

`install.sh` 会：

- 安装二进制到 `/opt/astock-v2-rewrite/bin/astock-v2`；
- 复制前端到 `/opt/astock-v2-rewrite/web`；
- 复制 `daily_auto.sh`、`daily_advance.sh`、`db_tool.py` 到 `scripts/`；
- 安装 systemd unit；
- **首次**从示例复制 `/etc/astock-v2-rewrite.env`；
- 不会自动启动，也不会覆盖已有 env 文件。

安装后核对环境变量：

```bash
sudoedit /etc/astock-v2-rewrite.env
```

至少应包含：

```dotenv
ASTOCK_V2_DB=/var/lib/astock-v2-rewrite/v2.sqlite3
ASTOCK_PRICE_SETS_DIR=/var/lib/astock-v2-rewrite/price-sets
ASTOCK_V2_ADDR=127.0.0.1:18765
```

然后安装 nginx 配置并启动：

```bash
sudo cp v2/deploy/nginx.conf /etc/nginx/conf.d/astock-v2-rewrite.conf
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl daemon-reload
sudo systemctl enable --now astock-v2-rewrite
```

注意：如果本机还有旧服务占用 8600，必须先停旧服务，否则 nginx 无法监听。

### 5.4 验证部署

在服务器本机：

```bash
curl -fsS http://127.0.0.1:18765/v2/health
curl -fsS http://127.0.0.1:8600/
systemctl status astock-v2-rewrite --no-pager
ss -ltnp | grep -E ':(8600|18765)'
```

预期：

- health 返回 `status: ok`、`schema_version: 2`、`paper_only: true`；
- 8600 返回页面 HTML；
- 18765 只监听 `127.0.0.1`，不是 `0.0.0.0`；
- 服务是 `active (running)`。

从外部网络再访问一次 `http://<服务器公网IP>:8600/`。本机 curl 成功只证明 nginx 和内核通，**不证明 OCI 安全列表和主机防火墙已放行公网**。

## 6. 日常操作

### 6.1 只读查看

```bash
# 当前覆盖和最后结算日
curl -fsS http://127.0.0.1:18765/v2/prices/coverage

# 账户总览
curl -fsS http://127.0.0.1:18765/v2/account

# 持仓、成交、调仓
curl -fsS http://127.0.0.1:18765/v2/account/positions
curl -fsS http://127.0.0.1:18765/v2/account/trades
curl -fsS http://127.0.0.1:18765/v2/account/rebalances
```

### 6.2 推进到最新交易日

页面上的“推进到最新交易日”等价于：

```bash
curl -fsS -X POST http://127.0.0.1:18765/v2/account/run \
  -H 'content-type: application/json' \
  -d '{}'
```

不传 `day` 时，服务使用当前价格集合的 `coverage_end`。也可以显式指定：

```bash
curl -fsS -X POST http://127.0.0.1:18765/v2/account/run \
  -H 'content-type: application/json' \
  -d '{"day":"2026-11-10"}'
```

行为：

- 从上次结算日的下一天开始，逐日补齐到目标日；
- 同一天重复调用返回原成交，`processed_days` 为空，不会新增交易；
- 目标日没有 reviewed 收盘价时返回 422，不会猜价格；
- 目标日早于最后结算日时返回 409。

## 7. 备份与恢复

### 7.1 为什么不能直接复制 SQLite 主文件

服务使用 WAL 模式。正在写入时，最新已提交内容可能还在 `v2.sqlite3-wal` 里；只复制 4 KB 的主文件会得到一个“看起来存在、实际没有数据”的库。旧库就出现过主文件只有 4 KB、真正数据在 WAL 的情况。

必须用 SQLite 在线备份 API。项目自带 `db_tool.py`：

```bash
sudo python3 /opt/astock-v2-rewrite/scripts/db_tool.py backup \
  --db /var/lib/astock-v2-rewrite/v2.sqlite3 \
  --out /var/backups/astock-v2-rewrite/v2-$(date -u +%Y%m%dT%H%M%SZ).sqlite3
```

它会：

- 以只读方式打开源库；
- 把 WAL 中已提交内容一起备份；
- 对备份做 `PRAGMA integrity_check`；
- 打印 schema 版本、账户数、已结算天数和 SHA256；
- 拒绝覆盖已有备份（除非 `--force`）。

### 7.2 验证备份

```bash
sudo python3 /opt/astock-v2-rewrite/scripts/db_tool.py verify \
  --db /var/backups/astock-v2-rewrite/<备份文件名>.sqlite3
```

预期：`integrity=ok`、`schema_version=2`、`accounts=1`（或实际账户数）。

注意：`db_tool.py` 只认新版的 `schema_version` + `account` 表；如果旧库缺这两张表，会报 “not a V2 rewrite database”。旧库请用 SQLite 自带的只读查询核对 `PRAGMA user_version` 和 `PRAGMA integrity_check`，不要试图让新工具“兼容”旧库。

旧库只读核对示例：

```bash
python3 - <<'PY'
import sqlite3
path = "/opt/astock-v2/backups/pre-v2-rewrite-20261111T151411Z/v2-schema15-20261111T071613Z.sqlite3"
connection = sqlite3.connect(f"file:{path}?mode=ro", uri=True)
try:
    print("user_version =", connection.execute("PRAGMA user_version").fetchone()[0])
    print("integrity =", connection.execute("PRAGMA integrity_check").fetchone()[0])
    print("tables =", connection.execute("SELECT count(*) FROM sqlite_master WHERE type='table'").fetchone()[0])
finally:
    connection.close()
PY
```

这里只读打开，不执行任何写操作；不要在旧库上跑新内核，也不要把 `user_version` 改成 0。

### 7.3 恢复

恢复会覆盖目标库，必须先停服务并再次备份当前库。下面的命令与当前 `db_tool.py` 的实际参数一致：

```bash
sudo systemctl stop astock-v2-rewrite
sudo python3 /opt/astock-v2-rewrite/scripts/db_tool.py backup \
  --db /var/lib/astock-v2-rewrite/v2.sqlite3 \
  --out /var/backups/astock-v2-rewrite/before-restore-$(date -u +%Y%m%dT%H%M%SZ).sqlite3
sudo python3 /opt/astock-v2-rewrite/scripts/db_tool.py restore \
  --backup /var/backups/astock-v2-rewrite/<要恢复的备份>.sqlite3 \
  --db /var/lib/astock-v2-rewrite/v2.sqlite3 \
  --force
sudo systemctl start astock-v2-rewrite
curl -fsS http://127.0.0.1:18765/v2/health
```

恢复前必须先停服务；`db_tool.py` 本身不会探测进程占用，也不会替你确认目标库不再被写入。`--force` 只用于明确覆盖已有目标文件，不能替代停机和二次备份。

## 12. 常见问题

### Q1：页面能打开，但点“推进”报错？

先看 `/v2/prices/coverage`：

- 没有价格集合：把 reviewed 集合放到 `ASTOCK_PRICE_SETS_DIR`；
- 覆盖结束日早于目标日：先取数并发布新集合；
- 目标日不是交易日：显式传一个覆盖内的交易日；
- 返回 `missing_close_price`：价格集合不完整，整批拒绝，不要补价。

### Q2：为什么调仓一直是 0 次？

按顺序检查：

1. 是否已经结算至少 2 个完整交易日；
2. 两个策略是否都有有效权益序列；
3. 评分差是否达到 100 bps；
4. 来源策略是否有足够可用现金；
5. 当前权重是否已经顶到 20% 或 80%。

以上任一不满足都会保持不动。页面“本次未触发调仓”是正常提示，不是错误。

### Q3：为什么账户收益和两个策略贡献相加对得上，但权重不是 50/50？

权重是预算参数，调仓只改预算；收益贡献按各自原始本金计算。两者口径不同，不能直接拿权重乘总资产来解释贡献。

### Q4：为什么服务启动就报 legacy database？

说明 `ASTOCK_V2_DB` 指向了旧 schema 15 库。保留旧库，换一个新的数据库路径，不要改 `user_version`。

### Q5：本地 `cargo test` 报找不到 `link.exe`？

这是 Windows MSVC 工具链缺链接器，不是代码错误。使用第 8.1 节的 GNU 工具链命令，或安装 Visual Studio Build Tools 的 C++ 链接器。
