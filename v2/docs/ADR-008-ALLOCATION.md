# ADR 008：动态资金分配（提案）

状态：已实现（提案 + 执行分离）。提案本身只读，基于审核净值序列给出受约束权重与理由；资金迁移由 ADR-009 的追加式划拨事件执行，控制台需二次确认；提案不自动触发划拨。

## 问题

固定 45% / 45% / 10% 只能表达“初始偏好”。要做到“根据已验证绩效调整配置”，需要：

- 用可信价格序列度量每个槽位的表现与风险；
- 把度量转换成分数（不是单看收益）；
- 在硬约束内生成目标权重，并能解释每一次调整；
- 明确“证据不足时不动”。

## 决定

### 1. 输入

- 账户（槽位预算、当前权重、槽位成交）；
- 一个 `reviewed` 价格集合，必须覆盖**整段请求交易日**；
- 显式交易日列表（与 ADR 007 一致，至少 2 天）。

### 2. 逐槽评分

对每个槽位独立重放其成交（初始现金 = 该槽预算），逐日盯市：

```
return_bps   = (最后一日权益 − 预算) × 10000 / 预算
drawdown_bps = 最大回撤 × 10000 / 预算
score_bps    = return_bps − drawdown_bps
days         = 序列点数
```

评分只做**槽位之间**的相对比较：`raw = max(score − min(score), 0)`。两槽一样差时保持均分，而不是把资金全给“亏得少”的一方。

### 3. 目标权重（默认策略）

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `min_slot_bps` | 1500 | 单槽下限 |
| `max_slot_bps` | 6000 | 单槽上限 |
| `reserve_bps` | 1000 | 准备金下限 |
| `max_step_bps` | 1000 | 单次调整幅度上限 |
| `min_days` | 2 | 生成提案所需最少观察日 |

计算顺序：均分/按 `raw` 分配可用资金 → 夹到 `[min, max]` → 归一到 `10000 − reserve` → 应用单次步长上限 → 余数计入准备金。

**硬约束**（违反即拒绝，不降级）：

- 目标权重之和 + 准备金 = 10000；
- 每槽在 `[min_slot_bps, max_slot_bps]`；
- 准备金 ≥ `reserve_bps`；
- 单次变化 ≤ `max_step_bps`。

### 4. 状态

| 状态 | 含义 |
| --- | --- |
| `proposed` | 目标权重与当前不同，附逐槽理由 |
| `unchanged` | 计算结果等于当前权重（含步长封顶后无变化） |
| `insufficient_evidence` | 任一槽 `days < min_days`，保持当前权重 |

### 5. 拒绝语义

- 无 `reviewed` 集合覆盖 → 端点返回 `unavailable + no_reviewed_price_set`；
- 交易日少于 2 天 → 422 `allocation_requires_two_days`；
- 参数非法、下限和超过 10000、准备金被突破 → 领域错误，不输出提案。

### 6. 只读

提案不写账户、不写成交、不改变槽位预算。每次响应携带 canonical `digest`，同一输入可复核。

## 验收（本轮）

1. 两日序列下，表现更差的槽位目标权重下降、更好的上升，且总和为 10000；
2. 目标权重全部落在上下限内，准备金不低于下限；
3. 单次调整不超过步长；
4. 观察日不足 → `insufficient_evidence` 且权重不变；
5. 合成集合不产生提案；未覆盖日期返回不可用；
6. 理由逐槽可读（评分与当前/目标权重）。

## 版本切换标注（已实现）

提案在计算窗口内若某槽发生过策略版本切换（`effective_from` 的中国日晚于窗口首日），该槽理由追加“窗口内发生策略版本切换，历史绩效来自旧版本”，并重算提案 `digest`；权重算法不变，不自动触发再平衡。

## 未决问题

- **如何执行划拨**：修改槽位预算需要新的账本事件（如 `rebalance`），当前账户预算由 spec 固定；需要单独 ADR 定义迁移与守恒。
- 评分口径：当前是“收益 − 回撤”，未做波动率/夏普；需要样本量与年化约定。
- 参数取值（1500/6000/1000/1000）是保守默认值，缺少回测依据，需在真实数据上校准。
- 是否允许准备金参与再投资：当前不允许，准备金只作缓冲。
- 提案的持久化与审计：当前按需重算，不落库。
