# ADR 008：稳健 / 激进的动态资金分配

状态：已实现。一个账户、一次本金、两个策略槽位，初始各 50%。每个完整交易日
结算后，根据“收益减回撤”评分在硬约束内调整两个槽位的**可用现金预算**。
不转移已经持有的股票，也不把预算权重描述成真实资产占比。

## 问题

固定 50% / 50% 只能表达初始偏好。要做到“根据已验证绩效调整配置”，需要：

- 用可信价格序列度量每个槽位的表现与风险；
- 把度量转换成分数，而不是只看累计收益；
- 在硬约束内生成目标权重，并能解释每一次调整；
- 证据不足或来源现金不足时明确不动。

## 决定

### 1. 输入

- 账户的槽位现金、持仓、当前权重与成交；
- 一个 `reviewed` 价格集合；
- 至少两个完整交易日，从上次调仓日之后开始、截至本次运行日。

客户端不能自选评分窗口，否则可以只挑对某个策略有利的两天来改变资金比例。

### 2. 逐槽评分

对每个槽位使用自己的账本逐日盯市：

```text
return_bps   = (最后一日权益 - 上次调仓后首日权益) * 10000 / 首日权益
drawdown_bps = 窗口内最大回撤 * 10000 / 窗口峰值
score_bps    = return_bps - drawdown_bps
```

评分只做槽位之间的相对比较。分差以 bps 计，直接作为调整步长，再夹在每次
最多 10 个百分点以内；分差不足 100 bps（1 个百分点）时保持不动。这样避免
0.02%–0.28% 这类没有实际意义的微调继续写入调仓记录。

### 3. 目标权重

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| 单槽下限 | 2000 bps（20%） | 任何槽位不低于 20% |
| 单槽上限 | 8000 bps（80%） | 任何槽位不高于 80% |
| 单次调整 | 1000 bps（10 个百分点） | 一次最多移动 10 个百分点 |
| 最少观察日 | 2 个完整交易日 | 不足则不动 |

计算顺序：比较评分 → 分差不足 100 bps 记 0 → 步长夹到 `[-1000, 1000]` →
对称调整 → 两槽都夹到 `[2000, 8000]`，总和保持 10000。

### 4. 执行口径

- 调仓只划转来源槽位的**可用现金**；
- 两个槽位已持有的股票不卖、不转；
- 来源槽现金不足拟划转金额时，本次不调仓，交易日照常结算；
- 调仓金额 = 总权益 × 新旧权重差，随后以实际账本重新计算当日净值；
- 权重、现金、成交、当日净值和日运行标记在同一个 SQLite 事务提交。

### 5. 状态

当前实现只有两种可观察结果：

| 结果 | 含义 |
| --- | --- |
| 有调仓记录 | 权重与现金已调整，并写入当日记录 |
| 无调仓记录 | 证据不足、分差太小、结果等于当前权重，或来源槽现金不足；权重不变 |

“不调仓”的原因目前只体现在该次运行没有 `rebalance` 记录，不会额外写一条
状态行；页面和 API 不应把“无记录”误读为“已发生划转”。

### 6. 拒绝语义

- 无 `reviewed` 集合覆盖 → 拒绝推进，不下单、不估值；
- 审核窗口少于 2 天 → 照常推进，资金不变；
- 参数非法或权重越界 → 领域错误，不输出调仓；
- 行情集合缺任一股、任一日 → 整体拒绝，不插值、不补价。

## 验收

1. 表现更差的槽位目标权重下降、更好的上升，且总和为 10000；
2. 目标权重全部落在 20%–80%；
3. 单次调整不超过 10 个百分点；
4. 观察日不足 → 权重不变；
5. 来源现金不足 → 权重不变且交易日不失败；
6. 调仓当日记录的两槽净值与划转后的账本逐项一致，合计不变。

## 边界

- 权重是预算参数，不是账户真实资产占比；
- 评分窗口是“上次调仓后至今”，避免长期累计收益掩盖近期变化；
- 参数是保守默认值，缺少真实长样本回测依据，不能据此宣称已验证盈利能力；
- 纯模拟，不连接券商、不产生真实订单。
