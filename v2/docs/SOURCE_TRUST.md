# 行情来源信任与四类时间

本批明确当前离线证据的信任边界，并记录 Rust 接入端的实际接收事实。
没有实际供应商接入或认证证明，不能把本批结果称为“真实行情认证完成”。

## 所有者与消费者

不新增业务模块、crate、进程或依赖。

| 现有所有者 | 唯一职责 | 消费者与依赖方向 |
| --- | --- | --- |
| domain/contract | 区分导入命令 `QuoteImport` 与落库事实 `QuoteEvidence` | HTTP/Store/execution 使用纯数据契约 |
| domain/execution | 校验固定证据及离线执行规则 | Store 调用；只解析显式时间，不读时钟或外部行情 |
| store/mod | 记录首次实际接收时间、离线信任事实，独占证据与账本写入 | HTTP → Store → Domain；Store 可读运行时时钟 |
| store/query | 对固定输入、结果、成交及证据快照进行只读核验 | API 消费；不重新导入或获取最新行情 |

两个数据契约体现真实的信任边界：外部导入者只能声明样本，不能提交服务器事实。
没有新增转发层、通用认证框架或预留供应商实现。

## 时间事实

| 字段 | 含义 | 当前权威 |
| --- | --- | --- |
| `quote.observed_at` | 样本声称的行情发生时间 | 离线样本声明，不保证市场真实性 |
| `available_at` | 离线样本声称在历史模拟中何时可见 | 离线样本声明，保留既有模拟行为 |
| `provider_published_at` | 实际数据提供方的发布时间 | 当前固定为 null，表示未知；没有供应商证明 |
| `received_at` | 本系统 Rust Store 首次接受新证据时记录的实际时间 | Store 在写入事务中读取系统时钟，格式为带 `+08:00` 的 RFC3339 时间 |
| 请求的 `decision_at` | 策略在历史模拟中的决策时间 | 显式研究提案，由 Domain 进行规则判断 |

`received_at` 是 Store 接受证据的时刻，不声称是网络首字节到达时间，
也不证明本机时钟获得了外部认证。它与样本声明的历史可见时间不混用。
历史离线样本可以在决策日之后才导入，仍按声明的 `available_at` 模拟；
真实接收时间如实保留为审计事实，绝不回填成样本时间。
未来真实供应商证据不能沿用该离线例外，必须通过独立验证过的接入路径。

## 信任等级与来源证明

- 当前只实现 `trust_level: "offline_fixture"`，由 Store 设置。
- 只接受来源 `offline-fixture`。自称真实供应商的来源仍被拒绝。
- 认证/已验证供应商等级没有实现；未知等级不能解析为合法证据。
- `provider_published_at` 必须为 null；离线证据不能凭自报值生成供应商发布时间证明。
- 当前没有供应商原始请求 ID、响应 ID 或发布时间证据，因此不生成或虚构这些值。
  未来实际接入若能取得这些原始事实，需要在对应版本化接入契约中原样保留并验证；
  不能只添加一个“verified”字段就提升信任。

## 导入、重复与研究边界

既有 `fixtures/quote.json` 和导入命令版本 1 保持可用：

```bash
curl --fail -H 'Content-Type: application/json' \
  --data-binary @v2/fixtures/quote.json http://127.0.0.1:8765/v2/quotes
```

返回版本 4 的证据，包含离线信任等级、未知供应商发布时间、实际接收时间、可选执行块及Store解析的固定离线证券身份。
未提供执行块的参考报价仍可导入，但新策略拒绝据此成交；执行块也只是离线声明，见 [EXECUTION_EVIDENCE.md](EXECUTION_EVIDENCE.md)。
导入命令不能包含 `received_at`、`trust_level`、`provider_published_at` 或虚构证明 ID；
这些未知字段返回 422。把完整落库证据重新当导入命令提交也返回 422。

同一 `(source, quote_id)`、相同声明内容重复导入，返回首次证据，接收时间不刷新；
不同内容仍返回 409。普通 API 没有覆盖或升级信任的入口。
Python 研究代码保持只产生 `quote_ref` 提案，不调用行情导入、不访问数据库，
不能设置成交数量、成交价格或接收时间。HTTP 只解析导入命令并调用 Store。
现有本地离线导入接口不等于研究请求获得供应商写入权；当前根本不存在供应商权威表或认证入口。

策略请求与回放都消费已经固定的证据。回放不读取当前时间、不查询供应商，
正常与拒绝决策都核对包括信任/接收字段在内的完整快照。

## 数据与验收边界

规则版本 `v2-paper-policy-6`，SQLite 文件 schema version 5，需全新 V2 文件；
旧文件在修改日志模式或 schema 之前拒绝打开，不自动迁移。

测试覆盖首次接收时间范围、重试/重开后保持原值、拒绝伪造字段和认证等级、
来源时间与信任语义不变，以及接收/信任字段篡改时正常与拒绝决策的回放失败。
HTTP 测试先行断言在旧实现上失败，再验证实现后完整链路。

CI 成功只证明上述代码行为，不证明市场数据真实或成交模型达到交易所精度。
来源信任阶段不接供应商或券商；后续固定日历/时段见 [CALENDAR_SESSIONS.md](CALENDAR_SESSIONS.md)。
完整订单、多账户、策略进化不在范围内，不合并或部署。
