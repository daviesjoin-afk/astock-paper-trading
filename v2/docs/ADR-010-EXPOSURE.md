# ADR 010：成本口径的组合敞口与集中度

状态：提议（Draft）。本轮落地**只读敞口分析**：不看市价，只按成交成本计算每个槽位、每个标的的占用与集中度，并与账户风险上限比较。

## 为什么用成本口径

ADR 006 要求“无可审核价格就不算市值”。敞口与集中度如果依赖市价，就会在数据缺失时失真或被迫伪造。成本口径只需要成交事实：

- 买入：数量增加，成本增加 `数量 × 成交价 + 费用`；
- 卖出：按**移动平均成本**减少成本（数量归零则成本归零）；
- 占用率 = 成本 / 当前槽位预算（预算按再平衡后的权重计算）。

它回答的是“已经投出去多少钱、压在哪个标的上”，不声称任何盈亏。

## 输出

`GET /v2/paper-accounts/{id}/exposure`

- 每槽：预算、现金、成本、成本占用率（bps）、逐标的（数量、成本、均价、占预算 bps）；
- 账户：总成本、总现金；
- `breaches[]`：任一标的发生本占比超过 `limits.max_symbol_weight_bps` 时给出 `symbol_concentration`（值/上限），不阻断交易、只报告；
- canonical `digest`。

## 边界

- 不读取价格集合，不依赖审核数据；
- 不计算市值、盈亏、收益率；
- 不写入账本；数字由成交事实派生；
- 卖出按移动平均成本，非 FIFO/LIFO；口径在响应中固定，不影响账本。

## 验收（本轮）

1. 买入后成本 = 数量 × 价格 + 费用，占用率 = 成本 / 预算；
2. 卖光后成本与持仓归零；
3. 超过单标的上限时产生 breach，值与上限正确；
4. 同一账户重复请求结果与 digest 一致；
5. 账户页展示“仓位与集中度”。

## 未决问题

- 卖出成本口径（移动平均 vs FIFO）是否需要可配置；
- 是否将 breach 升级为下单拦截（当前已在风控中按成本预检，此处只做监控）；
- 多币种/多市场扩展。
