## 2. 今天做了什么（按时间顺序）

### 2.1 数据层重建（解决了「只有 2 只股票」）

**上午的问题**：旧模型是「完整矩形 JSON + 人工 review 发布」，2 只股票 65 天 25KB 很优雅，
但 5000 只 × 250 天 = 125 万个点，单文件 200MB，每天全量重写，**不可能成立**。

**现在的模型**：

```sql
CREATE TABLE bar(
  symbol, day, name,
  open_cents, high_cents, low_cents, close_cents, prev_close_cents,
  volume_shares, amount_cents,
  adjust,   -- 'none' | 'qfq'
  source,   -- 'tdx' | 'v1-qfq'
  PRIMARY KEY(symbol, day)
);
```

关键变化：**从「整批要么全对要么全错」改成「逐条入库」**。新股、退市、长期停牌都不会让整批失败。

`prev_close_cents` 是从通达信盘后包直接读的，**这是唯一能区分"真跌停"和"除权跳空"的廉价手段**。
没有它，10 派 5 元会被画成一根 -20% 的柱子。

### 2.2 全市场摄取（`data_sources/ingest_market.py`）

一次 HTTP 请求（约 2.7MB）拿到沪深北全部证券当日的 OHLCV。

- **实测 2026-11-10：5576 只，9 秒**
- 包里有 5.2 万行（含 2.2 万债券、1.7 千基金、1.1 千通达信自编板块），**过滤掉 89%**
- 过滤后 5576 只真实股票（沪 2319 / 深 2902 / 京 355）
- 并发 8 线程实测**提速 7 倍**（2.3 小时 → 35 分钟补完 930 天）
- 幂等：同一天写两次结果一致

**没有做的**：不做抽样交叉核对、不做多源对账、不做人工 review。这是用户的明确决定。

### 2.3 导入 V1 归档数据（`data_sources/import_v1_klines.py`）

服务器 `/opt/astock-v1-archive-2026-11-07/` 里有 **16GB** 归档，其中：

- `data_cache/klines/` — **5574 个 CSV，491 万行**，2023-01-03 → 2026-11-06
- `db/paper_trading.sqlite3` — 2.9GB，85 张表，但只有 52 笔成交

**⚠️ 这批数据是前复权（qfq）的**，`kline_manifest.json` 明确记录：

```
"source": "eastmoney", "adjustment": "qfq"   ← 5568 只
"adjustment": "none"                          ← 5 只
"adjustment": "unknown"                       ← 2 只
```

**为什么这是坑**：前复权用「后来发生的分红送股」重写「历史价格」。你看到的 2024 年价格，
是 2026 年才能算出来的。用它做 walk-forward 回测 = 站在未来看过去，
而且**不会报错，只会让结果显得更好**。

证据：600036 有 850/930 行超过两位小数，起始价 `29.854`。真实报价只有两位。

**所以导入时打了标记**：`adjust='qfq'`。严格回测时加一句 `WHERE adjust='none'` 就过滤掉了。

### 2.4 性能：从「跑不完」到「可用」

第一次尝试 2.5 年全历史结算：**跑 5 分钟、CPU 600%、内存 1.2GB，还没算完**。

找到 **4 个 O(n) 线性扫描**：

| 函数 | 问题 | 修法 |
| --- | --- | --- |
| `PriceSet::contains` | 每次查价扫 400 万条 | 建 `IndexedPriceSet`，按天+按股票双索引 |
| `closes_for` | 每个结算日重建当日截面 | 走索引 |
| `bars_for` | 每次取个股历史扫全表 | 走 symbol 索引 |
| 信号计算范围 | 每天对 5315 只全算 | 只算当日有价的 + 已持仓的 |

再加两道护栏：

- `SETTLEMENT_WARMUP_DAYS = 120`：只加载结算日前 120 个交易日（策略最多需要 61 根）
- `MAX_SETTLE_DAYS_PER_CALL = 260`：单次请求最多结算 260 天，超了返回 `advance_too_large`

**实测结果**：

| 场景 | 耗时 |
| --- | --- |
| 单日推进 | **9.6 秒** |
| 9 天推进 | **13.5 秒**（1.5 秒/天） |
| 一个月（21 天） | **~20 秒** |
| `GET /v2/account` | **0.22 秒** |

### 2.5 策略重构（这是最曲折的一段）

**第一版问题**：原始策略一天进出好几次，一年 543 笔成交，**持有中位数只有 3 天，55% 不到 3 天就卖**。
000007.SZ 一年买了 11 次卖了 11 次。手续费花了 3202 元 = 本金 3.2%。

**第二版尝试（失败）**：加固定持有期（稳健 10 天、激进 5 天）。

- 成交从 543 → 145 笔（-73%）
- **但收益从 -2.44% 变成 -12.33%**，更差了
- 原因：激进策略在下跌时**想跑跑不掉**，只能眼睁睁看着

**第三版（当前）**：用户指出「持有时间不要固定死，应该看具体信号」。改成**评分 + 迟滞**：

```rust
ENTRY_SCORE = 40   // 评分 ≥ 40 才开仓
EXIT_SCORE  = -20  // 评分 ≤ -20 才平仓
                   // 中间 60 分是迟滞带，信号怎么抖都不动手
```

**权重是用真实数据校准的**，不是拍脑袋。统计 197 笔真实入场，按因子分四档看后续 5 日收益：

| 因子 | Q1（最小） | Q2 | Q3 | Q4（最大） |
| --- | --- | --- | --- | --- |
| 5 日动量 | **+0.55%** | -0.87% | -0.39% | **-3.22%** |
| 突破幅度 | **+1.80%** | -1.27% | -2.43% | -2.05% |
| 20 日涨幅 | **+0.97%** | -0.44% | -1.14% | **-3.32%** |

**三个因子全是「越小越好」**。唯一正期望的区间是「刚突破一点点」（0.02%~0.68%）。

所以权重设计成**奖励浅、惩罚重**——错过不是错，追高才是。对应常量：

```rust
FRESH_BREAKOUT_BPS = 100   // 突破超过 1% 就不再是"新鲜突破"
MILD_MOMENTUM_BPS  = 340   // 5 日动量超过 3.4% 算过热
MILD_RUN_UP_BPS    = 930   // 20 日涨超过 9.3% 算已经涨飞
```

另外加了**硬止损**（优先级高于评分）：稳健 -12%、激进 -7%。因为「扛住信号抖动」只在
逻辑没坏时成立，跌破止损再等只是加深亏损。

**三个版本对比同一年数据**：

| 版本 | 成交 | 收益 |
| --- | --- | --- |
| 原始（boolean 信号） | 543 笔 | -2.44% |
| 加固定持有期 | 145 笔 | -12.33% |
| **评分 + 迟滞 + 止损** | **131 笔** | **-9.32%** |

### 2.6 前端多级菜单（P2）

从「一个页面」变成 **3 个模块 / 9 个视图**：

```
总览  驾驶舱 / 今日信号
行情  全市场 / 个股详情 / 数据覆盖
交易  账户 / 持仓 / 委托与成交 / 调仓记录 / 推进与结算
```

- **手写 hash 路由**（`src/router.ts`，~120 行）：每个视图可分享、可刷新、可前进后退
- **手写 SVG 曲线**（`src/chart.ts`，~150 行）：一条线 + 日收益率柱状图，没引图表库
- 净值曲线是核心：账户/稳健/激进三条线可切，全部/半年/三月/一月四个区间可切

**顺手修的 4 个真实 bug**（都是 e2e 抓出来的，不是我发现的）：

1. **testid 重复**：账户数据在两个视图都有，渲染写到隐藏的那个，所以全是「—」
2. **曲线画不出来**：404 被吞掉，然后视图被标记为「已加载」不再重试
3. **320px 横向溢出 96px**：grid 子项 `min-width: auto` 让导航条撑破页面
4. **两个无障碍问题**：`role="tab"` 缺 `tablist` 父元素、11px 文字加 75% 透明度对比度只剩 3.5:1

### 3.4 新增 API

| 端点 | 用途 |
| --- | --- |
| `GET /v2/account/equity-curve` | **净值曲线**（账户+两槽，含最大回撤和峰谷日期） |
| `GET /v2/market/days` | 有数据的交易日列表 |
| `GET /v2/market/bars?day=` | 某日全市场截面 |
| `GET /v2/market/bars/{symbol}` | 个股历史 |
| `GET /v2/market/gaps?day=` | **除权跳空**（按板块算门槛） |
| `GET /v2/market/settlement-preview` | 结算视图诊断 |

**`/v2/market/gaps` 的门槛是按板块算的**，不是固定值：

| 板块 | 涨跌停 | 门槛 |
| --- | --- | --- |
| 北交所 | 30% | 3000 + 500 bps |
| 创业板 / 科创板 | 20% | 2000 + 500 bps |
| 主板 | 10% | 1000 + 500 bps |

> 为什么重要：用固定 11% 门槛时，2026-11-11 返回 34 只，**几乎全是创业板正常涨停**。
> 改后同一天返回 0 只；2026-06-15 正确返回唯一的上市首日股（+127%）。

## 5. 已知问题（重要）

### 5.1 激进策略在震荡市里是亏的

**这是当前最大的问题，而且是策略问题，不是 bug。**

那一年的实际成交，激进策略几乎每笔都是「买在高点、卖在低点」：

| 股票 | 买入 | 卖出 | 亏损 |
| --- | --- | --- | --- |
| 000011.SZ | 12.59 | 10.81 | -14% |
| 000007.SZ | 12.93 | 11.50 | -11% |
| 000058.SZ | 7.87 | 6.37 | -19% |
| 000031.SZ | 2.37 | 2.19 | -8% |

**已经做了的**：评分模型把入场从 203 笔压到 55 笔，且这些入场的表现明显改善：

| 月份 | 笔数 | 后续 5 日 | 胜率 |
| --- | --- | --- | --- |
| 2026-01 | 7 | **+2.35%** | **86%** |
| 2026-02 | 4 | **+2.01%** | 50% |
| 2026-03 | 6 | -1.43% | 33% |
| 2026-06 | 10 | -3.01% | 30% |

**1-2 月赚钱，3 月后转亏** —— 这说明是**市场状态问题**：突破策略在趋势市有效，在震荡市失效。

**没做的**：市场状态判断。这是下一步最该做的事（见第 7 节）。

### 5.2 其他限制

| 限制 | 说明 |
| --- | --- |
| **无鉴权** | 8600 页面和 `/v2/` API 完全公开。任何能访问的人都能创建账户、推进结算 |
| **未推送** | 19 个提交都在本地，GitHub 上没有，CI 没跑过 |
| **服务器是旧二进制** | 今天的所有改动都没部署，服务器跑的还是上午的版本 |
| **前复权数据不能回测** | 用 `adjust='qfq'` 数据做 walk-forward 会得出错误的乐观结论 |
| **样本量小** | 933 个交易日、约 60 笔激进交易，统计上不足以下强结论 |
| **无盘中撮合** | 只有收盘价，T+1，不接券商 |
| **无监控告警** | 只有 systemd 自动重启 |

### 5.3 不要做的事

- **不要**用 `adjust='qfq'` 的钱做严格回测
- **不要**让新内核打开旧 schema 15 库（`user_version > 0` 会被拒绝，这是故意的）
- **不要**把 `18765` 暴露到公网
- **不要**在没有当日不复权行情时手工改库「补一天」
- **不要**提交 `.data/`（已 gitignore，含 500MB 数据）

## 8. 今天踩过的坑（给接手人省时间）

### 8.1 V1 数据是前复权的

最容易误导人的一个。数据本身干净（抽样 100 只、9300 行，零空值、零非正价、零 OHLC 矛盾），
但**前复权 = 未来函数**。已经打了 `adjust` 标记，务必过滤。

### 8.2 固定持有期会放大亏损

直觉上「少交易 = 少手续费 = 更好」，但实测**收益从 -2.44% 变成 -12.33%**。
因为强制持有让策略在下跌时跑不掉。**正确的做法是让信号说话，不是让计时器说话。**

### 8.3 全市场「完整矩形」不成立

930 天里，5576 只股票中**只有 1 只**有完整数据。上市、退市、停牌都是日常。
所以 `from_bars` 改成「按每个标的自己的跨度」判断完整度，而不是要求全市场对齐。

### 8.4 grid 子项的 `min-width: auto` 会撑破页面

导航条是 flex row，放在 grid track 里。grid 子项默认 `min-width: auto`，
内容宽度（406px）会把 track 撑大，然后整个页面横向滚动，而不是导航条自己滚。
修法：`min-width: 0` + 显式宽度上限。

### 8.5 e2e 抓出了手工测试漏掉的 4 个 bug

手工看页面「看起来是对的」，但 e2e 发现：testid 重复导致数值全是占位符、
曲线根本没画、320px 溢出 96px、两个无障碍问题。**别只靠肉眼验收。**
