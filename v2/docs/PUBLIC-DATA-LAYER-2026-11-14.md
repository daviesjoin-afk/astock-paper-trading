## 本轮纠正的具体行为

- 旧 public_layer.py 不再把“不适合长回测”等同于“不接入”。全量查询由 PublicDataClient.datasets()/dataset() 暴露；旧 bars/valuation/industry CLI 保持兼容。
- Tencent 查询必须明确 raw/qfq/hfq，不能把 qfq 写成 adjust=none。旧兼容查询改为 raw，复用既有严格解析；STAR 成交量按股，其它支持板块按手转换。
- 缺失昨收、成交额、停牌状态返回 null，不写 0 冒充完整 bar；store_bars 预校验整批输入，拒绝缺字段或调整价，保留 tradable=false。
- 需要备用行情时必须实际执行备用调用，并返回来源、原始错误、缺失标的。逐股备用不冒充全市场完整日包。
- LLM 新闻与资金流任务已改为消费真实公共材料；有字段完整、符合时点的材料才运行，源失败只跳过相关任务。SDK→来源解析→任务载荷的离线端到端已验证，历史模式使用冻结快照。

## 时间与用途

当前快照用于当前选股/监控/LLM；近期窗口按实际覆盖日期使用；历史序列保留源观察日与抓取时点；财报报告期或行业生效日不证明当时已可见。计算器返回派生值并说明输入。严格 as_of 查询只用已冻结、可验证的历史快照，不抓今天的数据回填过去。

公开网站计算的资金流是来源定义下的统计值，不是交易所 Level-2 原始逐笔。保留其定义与单位即可用于研究，不得拿成交量假装净流入。

## 旧报告必须撤回的断言

- 原先 TDX package_missing_file 来源于测速调用向 parse_package 直接传入带连字符日期。正式 fetch_package 已做日期格式转换，没有证据支持“切换目录导致缓存路径变化”。
- 64 只 Tencent 测速当时全部成功，后续 HTTP 501 只能说明当时请求失败，不能声称在第 64 只永久被封。
- BaoStock 后续查询超时的成因未查清，不等于证实服务端排队、连续查询必定不可用。
- Python 取数性能的既有小样本支持先复用再按瓶颈优化；没有同口径 Rust 实现对照，不能断言重写收益为零。44–62 秒和 0.103 秒/只都是上一轮本机观测，不是本轮全市场实测或稳定 SLA。
- “曾变更行业占比 66%”不是“某个特定历史日期 66% 误分类”。也不能由已采股票子集推断全市场覆盖。

代码接入、离线行为验证、实际源站成功三种状态分别记录，不因测试通过就把所有源站写成可用。凭据、可选依赖或外网阻塞列出具体条件，并保留相应能力入口。
