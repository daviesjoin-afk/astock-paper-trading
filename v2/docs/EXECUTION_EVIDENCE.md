# 单档、单方向的离线执行证据

本次只建设“明确执行价/容量 → 纯Domain整笔通过或拒绝 → Store原子记录 → 固定回放”。
不实现部分成交、订单生命周期、排队或真实供应商。仍为单Cargo，无新业务模块或依赖。

## 审查结论与唯一职责

Quote.price_cents是离线参考价；tradable/limit标志没有给出买卖盘价格或数量。
QuoteEvidence证明Store固定了样本、信任级别和首次接收时间，不证明市场可成交。
原execution直接用参考价计算预算买入或全部T+1卖出；Fill只是模拟结果，不是外部回报。

复用contract定义类型、execution判断、Store独占不可变写入、query投影/回放。
消费者仍为HTTP → Store → Domain；Python只发信号与报价身份，TS不判断交易。
Fill通过所属run的quote_ref和证据快照追溯，不另存一份价格/数量事实权威。

## 最小契约和拒绝规则

现有QuoteImport/QuoteEvidence增加可选execution块。块的schema_version=1，字段为
quote_ref、order_side、price_cents、available_quantity、observed_at。
Buy表示供买单使用的卖方报价，Sell表示供卖单使用的买方报价；一个块只支持一个方向。
quote_ref必须等于父报价身份。必需字段缺失/未知字段、非法价格、负数量、错误版本/身份/时间拒绝导入。
零容量可以表达没有足够流动性。没有执行块的参考报价仍可保存，但不能成交。

执行价与参考价允许不同；实际预算/整手候选量只按执行价计算，不使用参考价回退。
候选量大于容量就整笔拒绝，不截成较小数量。缺执行块、方向不匹配、证据过期均拒绝且无Fill。
沿用现有固定180秒上限，完整Duration比较：恰好边界可用，多1ms拒绝；观察日必须是决策中国日期。
available_at仍约束可见时间；执行观察时间不得晚于它。Domain不读系统时钟。
这是离线模拟政策，不是实时市场报价的充分新鲜度标准或成交保证。

导入命令schema1保持，存储证据升级schema3，执行规则升级policy5。
SQLite表结构/schema4保持不变；旧policy4文件在WAL/DDL前拒绝，不迁移或重解释旧账本。
新规则使用全新V2文件，保留旧版本程序回放旧账本。

## 数量不重复使用：复用现有规则

当前单组合、禁止重复买入已持仓、T+1、卖出全部可卖lot、同中国日期的新鲜报价这几个约束，
共同保证同一不可变单向证据最多支持一次已提交成交：

- 买入后同日再买被已有仓位拒绝；这些lot不能同日卖出后再买。
- 卖出已取全部T+1数量；同日新买lot也不能成为再次可卖数量。
- 后一天不能重新使用该日报价；同身份导入不能刷新观察时间、容量或执行方向。
- 原信号重试返回原结果，不重复写Fill；不同策略/周期仍共享同一组合约束。

因此不另建容量余额表、派生缓存、消耗map或新增Fill字段。
增加跨信号/策略/周期、次日重用和真实SQLite重开/回放测试来验证这个前提。
未来引入部分成交、T+0、多账户或增仓时必须先重新设计容量守恒，不能沿用此证明。
不同quote_id的离线容量不证明真实市场新增流动性，本批不编造供应商序列号。

## 固定事实、失败测试与验收

Store同一身份对execution在内的完整内容保持不可覆盖；重复导入保留首次received_at。
trust_level仍offline_fixture，provider_published_at仍null，不接受自报认证或接收时间。
run继续固定完整证据及缺失，拒绝也落账；回放不用后补或最新数据改写旧结果。
成交和run同事务，失败回滚；历史PIT仅应用截止日以前的Fill。

先提交两个行为测试：仅参考报价在Domain应拒绝；Store应记录拒绝、幂等且回放无Fill。
旧实现预期返回Filled，必须取得真实红测试日志；不是编译错误。
实现后覆盖执行价不同、数量恰等/不足/零、方向错误、过期边界、字段缺失、身份/内容冲突、
重复导入/信号、跨信号容量前提、SQLite中途回滚/重开、篡改检测、固定回放与PIT。
Release、Python、锁定前端、HTTP/SQLite和全仓质量/安全/Docker/浏览器均以新HEAD检查为准。
