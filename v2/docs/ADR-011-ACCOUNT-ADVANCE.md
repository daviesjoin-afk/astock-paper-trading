# ADR 011：账户级按日推进与运行编排

状态：已实现（原提案已落地，证据见验收对照表）。本轮不做常驻守护进程，而是提供**可编排的账户级推进**：一次调用把所有运行中的会话推进到指定交易日。调度由外部 cron/任务系统驱动，服务本身仍是无状态循环。

## 问题

会话已经能单步/整段运行，但账户级操作仍要逐个会话点击。若未来接入定时任务，需要一次调用即可推进整个账户，且保持确定性：

- 不读机器时间；
- 不推进暂停/已完成会话；
- 不产生部分会话的“半日”状态；
- 结果可汇总、可审计。

## 决定

`POST /v2/paper-accounts/{id}/advance { "day": "YYYY-MM-DD" }`

1. 校验账户存在、日期合法（中国日）；
2. 列出该账户所有会话，仅处理 `status = running`；
3. 对每个会话调用既有 `advance_paper_session_to(day)`（只执行中国日 ≤ day 的信号）；
4. 汇总 `{sessions[], steps, filled, rejected}` 返回；无运行中会话时返回 `steps = 0`。

## 边界

- **不是**守护进程：没有内部定时器、没有后台线程，服务重启不需要恢复调度状态；
- 调度语义由调用方决定（例如 cron 每交易日收盘后调用一次）；
- 与单会话推进共享同一实现，不存在两套时间语义；
- 暂停的会话保持暂停，不因账户推进而被唤醒。

## 验收（本轮）

1. 两个运行中会话同时推进，暂停会话不动；
2. 跨两个交易日推进后，运行中会话完成；
3. 无剩余信号时推进为 no-op；
4. 非法日期 422、账户缺失 404；
5. 控制台提供账户级日期控件。

## 未决问题

- 是否需要在账户级引入“运行计划”（每日目标、失败重试）或直接交给外部调度；
- 多进程部署下的并发推进：当前依赖单进程写者；若横向扩展需要显式租约；
- 定时评估（资金再平衡提案）是否纳入同一推进调用（目前分离，避免隐式资金动作）。
