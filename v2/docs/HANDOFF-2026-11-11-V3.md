## 2. 本机环境（最容易踩的地方）

### 2.1 工具链：必须用 GNU

```bash
export PATH="<USER_HOME>/.cargo/bin:$PATH"
cd <PROJECT_ROOT>/v2
cargo +1.99.1-x86_64-pc-windows-gnu test --locked --all-targets
```

**为什么**：本机默认工具链是 `1.99.1-x86_64-pc-windows-msvc`，但**没装 MSVC 构建工具**。
报错长这样：

```
error: linking with `link.exe` failed: exit code: 1
  = note: link: extra operand '...cgu.0.rcgu.o'
```

这不是缺链接器——PATH 里的 `/usr/bin/link.exe` 是 Git Bash 自带的 **coreutils `link`**
（硬链接工具），不是链接器。

**不要**照抄旧文档的 PowerShell 绕法（设 `CARGO_HOME` / `RUSTUP_HOME` / `.toolchain\mingw`）——
那些目录本机根本不存在。GNU 工具链是全局装好的，直接用即可。

### 2.2 端口：六个不同的默认值

| 组件 | 位置 | 默认端口 |
| --- | --- | --- |
| Rust 内核 | `v2/src/main.rs:625` | **8765** |
| Vite dev | `v2/web/vite.config.ts:3` | **8765** |
| Vite preview | `v2/web/vite.config.ts:6` | 18766 |
| `daily_cycle.sh` | `v2/scripts/daily_cycle.sh:30` | **18765** |
| 部署 env 样例 | `v2/deploy/astock-v2.env.example` | 18765 |
| nginx | `v2/deploy/nginx.conf:24` | 反代到 18765 |

**本机跑 `daily_cycle.sh` 必须显式传 `ASTOCK_API`**，否则它去打 18765 而你的内核在 8765：


## 5. 本轮做了什么：P0' 市场状态判断

### 5.1 为什么

激进策略是突破规则。同一年数据里它 1-2 月每笔赚 +2.4%，3 月后每笔亏 3%——
**同一份代码**。这不是规则坏了，是趋势跟随规则跑进了一个不再趋势的市场。

### 5.2 怎么做的

`v2/src/domain/regime.rs`，纯函数。每个结算日先定状态：

| 状态 | 判据 | 激进槽 |
| --- | --- | --- |
| `trending` | 等权指数 MA20 高于 MA60 ≥50bps，**且**过半标的在自己 MA20 之上 | 基线（入场 40，单票 30%，3 只） |
| `choppy` | 指数在 ±50bps 内，或趋势没广度确认 | 入场 **40→60**，单票 30%→20%，3→2 只 |
| `declining` | MA20 低于 MA60 ≥50bps | **不开新仓**，出场和止损照跑 |
| `unknown` | 历史不足 60 天 | 按 `choppy` 处理（绝不放宽） |

**稳健槽完全不受影响**——它的评分已经在个股层面要求趋势+低波动，再卡一次是重复计数。

### 5.3 三个刻意的决定

1. **等权指数，不是沪深 300**。行情源没有自由流通市值，且策略本来就全市场选股。
   同时用 `index_eligible_symbol` 排除基金/债券/指数代码——否则 2.2 万只债券
   会把这个"股市"变成债市。
2. **下行优先于广度**。实测 2026-08-14：指数在 MA60 下方 1063bps，但 81% 的个股
   在自己 MA20 之上（急跌后短反弹）。如果先看广度，会在下跌中途重新打开激进槽。
   所以 `declining` 只看指数，广度只能**确认趋势**、不能**否定下跌**。
3. **可关闭**。`ASTOCK_V2_REGIME_FILTER=0` 回到过滤前。加过滤器的理由是个可测量
   主张，那它必须保持可测量。

### 5.4 A/B 实测（同一份数据）

171 个交易日（2026-03-02 → 2026-11-09）、77 万行、5576 只、本金 10 万。
前 120 天热身，后 50 天逐日重放。

| 指标 | 不过滤 | 加过滤器 | 差 |
| --- | --- | --- | --- |
| 总资产 | ¥9,358,061 | **¥9,487,860** | **+¥129,799** |
| 总收益 | -641 bps | -512 bps | +129 bps |
| 稳健槽 | -739 bps | -422 bps | +317 bps |
| 激进槽 | -544 bps | **-601 bps** | **-57 bps** |
| 成交 | 78 笔 | 48 笔 | -30 |
| 期末持仓 | 2 | **0** | -2 |

**这张表很容易读错，务必看这里：**

- 总资产 +12.98% **不是激进槽赚的**。激进槽收益率反而低了 57bps——少 30 笔交易
  让它错过了 9 月底反弹。真正好处是**期末空仓**：那段 5 个抽样日里 3 天 `declining`，
  过滤器让它在下跌里不进新仓，也就没有持仓扛回撤。
- 稳健槽 +317bps **与过滤器无关**（策略没改）。那是现金再分配：激进槽少占资金，
  `slot_equity_day` 变了，调仓时现金分布跟着变。读成"过滤器改善了稳健策略"就错了。
- **样本只有 50 天、单一市场状态，不足以说明跨周期期望收益。** 它能说明的是：
  过滤器没把事情变坏，且显著降低了下跌期的仓位暴露。

### 5.5 顺手做的

- `IndexedPriceSet::recent_closes`：regime 只要数字，不用每行分配 `Bar` + clone symbol。
  5.5k 只 × 120 天是 66 万次无谓分配。
- `Store::market_regime`：走 `adjust='none'`，和结算同一口径。
- `Store::regime_filter` + `ASTOCK_V2_REGIME_FILTER=0` 开关。

## 7. 已知问题

### 7.1 策略层

| 问题 | 说明 |
| --- | --- |
