## 行为对照

同一 Windows / Python 3.14 / 项目虚拟环境；两份独立 checkout；freezegun 固定到 2026-10-30 17:00:00（UTC+8）；复用现有离线真实账本夹具，不访问在线行情。验收工具依赖 freezegun 安装在临时工具目录，没有加入应用依赖。

每边 8 个场景均通过。比较风险返回结果及 11 张表所有列，包含订单、成交、账户、持仓、lot、资金预占、NAV、审计、cycle、风险状态与风险决策。10 个检查点共 3,285 个账本字段逐值一致；不删除时间戳、ID、价格、数量、资金或审计字段。JSON 序列化仅用于跨进程传递。

检查点包括：周期切换拒绝；完整风险卖出；部分风险卖出；风险审计恰好一次；恢复 300 股→同事件重复零新增成交→新事件再成交 700 股；完整交易回放；真实恢复入口 fencing 失败前后账本完全相同。

规范化 JSON（sort_keys=True，ensure_ascii=False）SHA256：356b90f1ab0693906f757e5045ac5407357bfb3e67b612d46fe6a42da39ddf38。

注意：上述业务测试复用真实风险/执行函数；盘中编排另由顺序、非空结果透传、空结果复用、异常中断测试验证。它不能证明所有市场输入均等价。

复跑方式：在两份 checkout 根目录分别运行同一份 `scripts/pr298_ledger_probe.py <输出文件>`（用绝对脚本路径）；给验收 Python 环境安装 freezegun，然后用 `json.load` 读取两个输出并断言完全相等。探针仅写临时测试账本。

## 隔离编排性能对照

两边各 20 次；相同响应和延迟：健康检查 2ms、全市场响应 30ms、风险 10ms、恢复 5ms；全市场响应均为空（degraded / scan_ready=False），无数据缓存，数据库以隔离替身代替。运行实际 monitor_intraday，测量真实墙钟，不冻结性能时钟。

| 指标 | 基线 P50 / max ms | 修改后 P50 / max ms |
|---|---:|---:|
| 风险启动延迟 | 69.376 / 80.075 | 3.629 / 25.499 |
| 风险服务替身耗时 | 10.863 / 11.189 | 10.898 / 11.049 |
| 本轮隔离扫描耗时 | 86.862 / 139.679 | 88.075 / 124.912 |

每次调用均为 health=2、market snapshot=2、risk=1、resume=1；两边所有返回结果一致。调用数指服务边界次数，不等于内部 HTTP 请求数。固定延迟下主要变化是风险启动更早，总耗时未显示改善。锁等待没有被测量（数据库替身，无锁竞争）；调度跳过次数没有被测量（直接调用，没有调度器）。

复跑：两边分别运行相同 `scripts/pr298_timing_probe.py <输出文件>`。P50/max 属于小样本隔离编排结果，不能外推到真实全市场扫描、真实 provider、锁等待或 skipped slots。真实 provider 请求、调度跳过和争锁性能仍未验证；本 PR 未部署，不以本数据宣称线上提速。

## 异常语义

monitor_risk 或恢复入口抛出 RuntimeError / paper lease lost 时，monitor_intraday 原样抛出并停止后续处理。风险失败时不执行恢复；恢复入口失败时不执行全市场刷新。异常没有改成成功、空列表或重试完成。

恢复前置确实改变失败的发生位置：基线已刷新市场才失败，现在先失败而没有候选扫描。这符合本实现的 fail-closed 顺序，但会牺牲失败轮的候选可用性，需要人工审核。恢复函数内部已有的逐订单异常回滚、可重试标记仍由原函数处理；本 PR 未改变它们。
