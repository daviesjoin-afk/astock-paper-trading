# 仓库规范检查（2026-09-05）

结论：具备可使用的开源项目基础，但还不能称为工程治理完善的项目。GitHub Community Profile 当次返回 85%；该分数只反映文档覆盖，不代表安全或代码质量认证。

## 已有基础

- MIT LICENSE、中英文 README、贡献指南、SECURITY.md、架构文档、运行手册和 CHANGELOG。
- Bug/功能建议 Issue 表单、PR 模板、Python 3.11/3.12 回归、语法检查、Docker 冒烟。
- v1.1.0 发布说明列出升级、回滚、实际验证范围和已知限制。

## 已纠正文档

- README 补充发布入口、受 CI 覆盖的 Python 版本和内部 API 版本与发布标签的区别。
- 明确本地 Compose 端口默认暴露所有网卡，应用尚无完整内置认证。
- CHANGELOG 澄清 v1.0.1 未单独打标签，完整修订由 v1.1.0 发布；Release 不再只有标题。

## 尚需治理

1. 主分支保护当前未开启；应配置必需 CI、禁止强推和删除。本次检查未改变仓库权限规则。
2. 依赖未锁定，CI 未执行完整 lint、依赖漏洞审计和覆盖率门槛。
3. 尚无 CODE_OF_CONDUCT；SECURITY.md 的私下报告渠道不够具体，应由维护者确认实际可用渠道。
4. API 版本字段与 Release 标签并非同一来源；后续应提供可追踪的构建提交标识。
5. 核心编排文件仍大，完整回放契约、前端模块化、统一身份来源尚未完成。
6. 历史交接文档含环境相关路径且状态可能过期，应与通用部署文档分开。文档声称不含服务器路径过于绝对，后续应逐项收敛。

本次为文档、仓库配置及既有 CI 的检查，不是完整渗透测试或历史 Git 凭据审计。未为追求模板数量添加无实际维护流程的政策文件。
