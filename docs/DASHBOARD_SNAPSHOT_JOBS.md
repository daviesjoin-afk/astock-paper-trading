# Dashboard 快照持久任务

PR-2 基于 PR-1 合并提交 `c321e394c25f034af8938fa007b4643c62e37369`。交易任务现在只登记展示刷新请求，立即按原交易结果结束；慢快照刷新由独立进程处理。展示失败不再使已经完成的交易任务以失败退出。风控、候选、成交与行情证据规则未修改。

## 职责和状态

`paper_schema_migrations` 持有新增表 `paper_dashboard_refresh_jobs`，正式迁移为 v41。此表独立于 `paper_jobs` / `paper_job_runs`，不混入交易运行统计，且只有 `paper_job_lifecycle` 写入；`paper_snapshot_jobs` 组织短事务与 worker 的刷新过程。

队列只有一个固定身份，重复排队合并。状态为 queued → running → completed/failed。请求版本与认领版本分开记录：运行中到达的请求保留为一次后续排队，不丢失，也不展开成无界队列。记录 trigger、请求/开始/心跳/结束/最近完成时间、attempt、错误和下次重试时间。

租约为 120 秒，每 20 秒心跳；失败后至少 60 秒再试。新请求不跳过失败退避。进程退出不丢失队列，租约到期后新进程用递增的 fencing token（区分新旧持有者的代次）认领；过期持有者不能续期、完成或发布。没有独立的交易运行权，也不会提交订单或改变资金。

快照的行情/新闻/板块收集和原计算均在 SQLite 写事务外执行。文件发布前进入短写事务，校验当前 owner、代次和未过期租约，再发布趋势历史与快照并完成任务；其它 worker 不能在此期间认领。快照文件继续使用临时文件和原子替换。数据库与两个 JSON 文件不是跨介质原子事务：如果进程在文件落地后、任务提交前退出，任务会恢复并重新刷新；已有快照保留，队列不假装已完成。该边界不涉及交易账本回滚。

## 调用与部署配置

`request_risk_snapshot_refresh` 现在始终持久登记，不创建刷新线程。旧 `background` 参数仍可传入，但不再选择同步路径；`wait_risk_snapshot_refresh` 只读状态，不等待。原兼容回调只在登记后用于本进程缓存失效，不能把持久任务回滚。

`run_slot` 在交易租约释放后为 intraday/risk 登记请求；即使登记失败，也保留交易成功结果并在返回中记录展示错误。计时阶段改名 `risk_snapshot_enqueue`，不能把它当成完整刷新耗时。独立 worker 命令：

```bash
python backend/paper_snapshot_worker.py
```

每次运行只处理一个待处理或已到重试时间的任务；无任务即退出。仅 completed/idle 返回 0，刷新失败或丢失租约返回非零。worker 进程执行刷新，唯一的辅助线程只续心跳并在退出前停止，不承担后台刷新业务。

Linux cron 每分钟在现有 `astock-data-worker` 中执行上述命令，持有 `resource-heavy.lock`，不经过交易 `run_paper_slot.sh`，不持 `paper-scan.lock`，也不增加交易并发。锁被历史恢复/候选数据任务占用时本次不进入 worker，持久请求留到下一次。因此这是有恢复能力的展示解耦，尚不保证一分钟内刷新，也未证明 SQLite 争锁或真实 provider 请求减少。

Windows/非 cron 环境应由现有任务管理器定期调用同一命令；本 PR 没有远程安装任何任务。上线需单独批准：使用固定提交/镜像、执行 v41 迁移，再同步 cron，确认 worker 与交易各角色身份一致。当前只交付代码，未部署。

## 页面契约

GET risk-overview 和 POST risk-refresh 都立即读取最近成功快照；缺失/陈旧或手动刷新时仅排队。兼容的 `allow_network=True` 也不允许页面线程同步采集。实际联网刷新只有 worker 的显式入口。

返回保留 asof、snapshot_age_seconds、snapshot_stale 与原数据源时间，并添加 snapshot_refresh 中的状态/错误/尝试次数/最近完成时间。刷新失败显示原错误和旧快照；排队、刷新中或失败等待重试时可继续轮询。缺少快照时年龄为未知，不伪装成 0 秒或已刷新。跨进程完成通过原数据库/WAL 缓存代次失效读取缓存。

## 回滚

获得独立发布批准并上线后，如需回滚，先停止新增展示 cron 入口并排空当前展示 worker，再恢复旧代码/镜像和原 cron；保留当前交易账本，不用旧备份覆盖合法成交。v41 只有独立展示表的新增，旧版可忽略它，无需为了代码回滚删表。未完成展示请求留表供后续决定恢复，不把其状态改为成功。旧版会恢复同步展示等待行为，应把该可用性影响记入回滚记录。
