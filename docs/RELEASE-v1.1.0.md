# v1.1.0 — 运行设置、五策略与恢复流程修复

本版本汇总 v1.0.0 之后的功能和维护更新。仅用于模拟交易；不包含运行账本、行情缓存或凭据。

## 新增和调整

- 设置中心统一管理默认资金、周期长度、下一周期策略集合、共享池风险参数、策略覆盖参数和 AI 研究配置。变更通过白名单校验并记录审计；资金与策略集合在下一周期生效。
- 五套注册策略全部支持新周期，保留既有历史周期和审计记录。
- 最小建仓金额依据周期本金、共享池敞口、席位数和席位利用率计算，替代固定金额门槛；默认利用率为 60%。
- 保留决策规则、行情适配、账本读模型、资金分配和影子风险模块的渐进拆分；巨型编排模块仍待进一步治理。
- 移除独立个股研究页面及历史静态资源镜像，保留模拟盘策略证据入口和相关后端兼容接口。

## 修复

- 统一主脚本与旧路径兼容镜像，修复前端镜像检查失败。
- 日常 SQLite 备份使用 gzip，修复校验清单与恢复目录布局。
- 备份、恢复、健康检查和告警脚本在 Git 中保存可执行权限，避免 cron 直接调用时 Permission denied。
- 恢复先验证校验和并在独立目录解压，对 SQLite 执行 integrity_check，再停止所有当前运行的 Compose 服务，包括 paper worker。
- 停服后保存原数据库和 WAL/SHM 文件，再替换数据库，保留文件权限；健康检查失败时再次停服并回滚。校验失败不会触发删除当前数据目录。
- 恢复不重建镜像、不清空整个数据目录，也不恢复 reports、行情清单或环境配置；这些内容应按运维需求单独管理。

## 验证

- 本地原有 209 项 unittest 通过。
- Linux 新增 3 项隔离回归通过：错误校验不触碰服务/数据、正常恢复、健康失败回滚；使用临时 SQLite 和模拟服务命令。
- PR #12 的 Python 3.11 / 3.12、语法和 Docker 冒烟 CI 全部通过。
- 修复提交已在服务器部署：容器健康、HTTP 健康接口返回 200；宿主机与容器内恢复脚本校验值一致。
- 没有在生产账本上实际执行恢复；隔离回归不等于所有故障场景均已覆盖。

## 升级与回滚

1. 保存当前提交、部署配置和独立的一致性数据库备份；确认备份校验通过。
2. 获取本版本标签并按既有部署方式构建启动；保留原数据挂载。
3. 检查健康接口、设置中心、五策略概览及后台任务日志。新策略集合只影响下一周期。
4. 如需恢复数据库，先在副本演练，并在维护窗口运行 `APP_DIR=/path/to/project ./deploy/restore.sh --confirm-restore /path/to/backup`。宿主机需要 Bash、Docker Compose、sqlite3、gzip、coreutils 和 flock。
5. 恢复脚本只恢复四个白名单账本，并保留恢复点。数据库结构发生变化时不要只回退源码，应使用与目标版本兼容的备份。

## 已知限制与后续工作

- 应用尚无完整内置身份认证；`confirmed=true` 不是鉴权。默认本地 Compose 的 8600 映射绑定所有网卡，外网使用必须先配置访问控制、认证和 TLS。
- Release 标签为 v1.1.0；API/OpenAPI 仍沿用历史内部版本 2.0.0，不能据此判断部署提交。
- 依赖仍是版本范围而非锁文件；CI 验证 Python 3.11/3.12，不能推断所有更高版本均兼容。
- 大文件拆分、完整回放契约、前端模块化、主分支保护等工作尚未完成。
