# 逐笔归因的 AI 配置

逐笔归因使用统一 AI 槽位，与盘后数据质量研究共用配置解析和公共传输层。当前 provider 选择按现有别名映射到 `ai1`／`ai2`；默认 `deepseek` 对应 `ai2`。槽位所绑定的实际提供商、地址、模型、密钥与超时以设置中心保存值为准。

不再用旧的厂商环境变量密钥判定是否可调用。清空密钥、禁用槽位、地址或模型缺失时，在请求前保留规则归因，不静默切换到另一个槽位。提供商调用或响应解析失败时也保留已计算的确定性字段。

成功记录中的 `ai_provider` 保存实际槽位；归因运行记录的 `provider`／`model` 保存实际槽位与模型。返回结果的 `analyzed`／`deterministic` 分别表示 AI 完成和保留规则回退的数量。查看降级时应同时检查这两个计数和 `error_code`，不能只看整个学习任务是否 completed。

正常入口仍是既有盘后学习流程。本次修复不改变账户权重、风控、交易规则或调度。规则归因先落库，网络调用在数据库事务之外执行。

每次最多分析 5 条，要求短摘要，输出预算为公共传输层的 4,000 token 上限；调用超时仍使用槽位配置。这样避免一次塞入过多归因导致生成超时或输出被截断。
