## 按策略准备因子

原来的评分已按策略区分权重；重复工作发生在公共因子表仍全量计算评分列。
现在 `strategies.scoring_factor_inputs` 从现有权重键确定评分依赖，
`paper_trading._candidate_rows` 根据实际生效模型传入依赖，不按账户名固定猜测。
标准化指把不同量纲的原始数值转成可比较的横截面评分。

| 模型 | 按需准备的标准化评分因子 | 仍保留的其他依赖示例 |
| --- | --- | --- |
| 强势接力 one_to_two | 短动量、资金、量能、情绪 | 首板、价格、过热检查、共同辅助排序 |
| 趋势回踩 bottom_reversal | 估值、质量、量能、资金、短动量、反转 | 均线、原始 RSI、趋势位置 |
| 演化后的 trend_continuation | 短/中期动量、资金、量能、质量 | 均线结构和已生效演化条件 |
| 板块轮动 sentiment_pioneer | 情绪、资金、短动量、量能 | 板块热度、早期轮动、独立强势条件 |
| 披露利润 reported_profit_breakout | 使用原有原始规则，不准备通用复合评分列 | 连阳、均线、已披露利润、超大单排序 |
| 主力 main_force_top10 | 使用原有原始规则，不准备通用复合评分列 | 流入强度、成交额、换手、市值和板块扩散 |

原始事实、硬条件、辅助排序和必要的审计依赖不能仅因未出现在权重表里而删除。
本批仍保留通用资金上下文；未使用的通用情绪评分保持未知，不伪造为零。
未声明完整依赖的扩展模型、声明式 DSL 及未传新参数的旧调用仍保留完整因子输入。
本批先裁剪评分计算，没有声称已裁剪所有原始字段、财务取数或盘后日线因子构建。

对照回归保持候选顺序、分数、证据质量、已生效权重和阻断结果；候选审计中未使用的评分列会减少。
所需情绪缺失时，板块策略仍不能生成正式候选。额外的因子依赖清单记录在候选元数据中。

## 输入和分时复用

`CandidateScanInputs` 保存本轮首次可用的股票基础信息、财务快照；每个策略拿独立副本，
失败或空响应不缓存，下轮创建新对象。股票和财务源原本已有底层缓存，这一改动主要明确
同轮事实与数据归属，减少入口重复调用，不能据此宣称减少同等数量的远程请求或 SQL。

分时序列和微结构共享有效原始分时响应，适用于同进程有效期内的串行消费。
派生缓存沿用原始请求开始时间，不从第二次消费时间延长有效期。
失败、空响应、末行格式损坏不缓存；历史日期不使用实时缓存；缺失证据仍返回未知或 partial。
跨进程和并发同键请求的合并不在本批范围内。原有单源重试预算和五线程上限保持。

## 基线口径与使用

```bash
python backend/paper_scan_baseline.py reports/scheduler.log --date 2026-10-21 --output scan-baseline.json
python work/verify_scan_input_reuse.py
python work/verify_scan_input_reuse.py --full
```

基线格式为 v2：同版本同日的 `session_coverage` 合并各类结束日志，只描述整场样本覆盖；
`groups` 仍把正常、降级、失败和实际扫描路径分别统计耗时。没有可信开始时间时，
`missing_scheduled_minutes` 为 null，`coverage_status` 为 unknown，不虚报 78 次调度缺失。
开始时间可能因等待锁偏移，观察到的分钟缺口不等于调度失败。

`observed_failure_fraction` 仅计算 failed / (completed + failed)，不把 in_progress 计为已完成，
也不推断没有结束日志的任务结果。阶段调用/异常只汇总明确上报的计数；阶段调用包含内部重试，
不等于 HTTP 请求数。含并行和子阶段的耗时不能相加。冷启动仍只按已确认 attempt_id 另列或排除。

重新整理的旧日志仍是 67 条：completed 63、failed 1、in_progress 3；版本、来源和开始时间未知，
不能证明当前版本的整场 P95 或调度覆盖。新版本真实性能仍需完整交易时段的自然样本。
