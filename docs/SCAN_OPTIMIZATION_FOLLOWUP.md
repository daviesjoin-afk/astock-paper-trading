# 备份、指标与扫描准备优化（2026-10-20）

## 范围和行为

本轮只处理两项收尾、自然扫描基线、微结构取数及交易候选的事务前准备。
系统仍只使用模拟资金；策略阈值、独立源成交核验、周期/运行权重验、唯一成交提交不变。

- WAL 是 SQLite 暂存尚未归并修改的日志文件。备份目录允许 SQLite 创建/维护它所需的共享内存文件，源连接仍使用 `mode=ro`。
  本地回归执行真实备份 shell 和内嵌 SQLite 代码；服务器另外使用真实 Docker 挂载和活跃 WAL 验证。
- v37 为任务最近行和审计最近行增加匹配索引。正常初始化同样安装索引，指标端点只读消费，
  不创建索引。任务排序以 `run_key` 确定同秒记录的顺序，审计仍按 `id` 取最新，未改成按写入时间排序。
- `paper_timing` 增加 UTC+08:00 开始时间、运行版本、快照来源/降级状态和门禁结果。
  显式 worker 绑定只共享诊断上下文，不继承数据库或租约上下文；并发计数有锁保护。
  诊断读取异常不能打断风控。
- 微结构的 requests 主机轮换和 curl 回退共用原有一轮主机轮换的预算，默认三台主机各四秒。
  快速失败仍可转 curl，耗尽后不再启动另一整轮等待。requests 的超时是套接字无活动时限，
  因此十二秒是重试发起预算，不是已发请求或整批任务的硬截止承诺。
  部分来源失败继续返回 `partial`/未知字段，`score_applied=False` 不变。
- `paper_candidate_scan` 拥有事务前的逐策略准备、轮内计算复用、微结构去重取数、冷却/新闻/报价采集。
  报价最后获取，账号之间的报价和板块证据独立复制。主编排仍负责因子门禁、写事务、周期重验和信号提交。
  这是一个真实准备边界的迁移，不代表全部候选评估或买入编排已经拆完。

## 已取得的基线

从服务器取回 2026-10-20 的 67 条自然 intraday 记录；其中 62 条带风控和候选阶段的 completed
记录，中位数 113.185 秒、观测 p95 279.916 秒、最大 401.321 秒。另有一条完整路径失败、
三条 in_progress 提前返回和一条没有扫描阶段的短完成记录，分组报告不会把这些记录计成提速。

旧日志没有运行版本、来源和开始时间，且当天多次部署、发生行情降级，不能把这一组当作同版本、
同数据条件下的性能承诺，也不能从开始时间缺失推断任务没有启动。
新格式需要在下一个完整交易时段自然积累；本轮不强制执行真实交易任务凑样本。

受控超时模型中，单个微结构来源的配置等待从 27 秒（三次 requests、三次 curl）降到 12 秒
（三次 requests，预算耗尽后不再启动 curl）。该模型无真实网络等待，只验证请求放大和预算规则，
不能折算为整轮节省十五秒或证明真实来源恢复率不变。

## 使用方式

```bash
python backend/paper_scan_baseline.py reports/scheduler.log --date 2026-10-21 --output scan-baseline.json
```

报告按运行版本、业务日、任务结果、快照来源、降级状态和实际扫描路径分组。各阶段包含子阶段及
并发工作，不能相加。冷启动只允许按已确认的 attempt_id 显式排除，并保留未排除的原报告：

```bash
python backend/paper_scan_baseline.py reports/scheduler.log --date 2026-10-21 --exclude-attempt ATTEMPT_ID
```

样本不足、缺少版本/来源或不能覆盖调度时刻时，p95 明确标记为暂定。
开始时刻覆盖只反映日志样本，不证明调度器、交易日历和策略通道全部运行正常。
