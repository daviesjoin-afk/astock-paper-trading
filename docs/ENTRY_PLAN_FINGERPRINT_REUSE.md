# 买入审批：去掉重复行情指纹计算

每个候选先生成组合分配计划，执行前再读取事实并重验。旧调用方在两个阶段各计算一次全市场行情指纹，
组合事实服务对同一份输入又计算一次；这会把“生成计划 + 重验”的行情指纹计算从两次增加到四次。

本批仅移除三个内部调用位置的重复参数：计划生成、共用重验、自动买入内联重验。
组合事实服务继续从实际行情生成身份；对外 API 的预期指纹约束与错误指纹拒绝行为保留。
最终重验仍重新读取行情与账本、重新生成组合快照，同时比较 snapshot_id 和 snapshot_fingerprint。
没有跨候选复用审批结论，也没有跳过周期、运行权、资金预占、持仓或成交约束。

新增两个计时阶段，沿用现有自然任务日志和基线统计：

- `execution.plan_build`：计划生成，包含行情读取、事实捕获、权重读取和分配计划。
- `execution.plan_revalidate`：最终重验，覆盖共用入口和自动买入内联入口。

阶段包含子阶段，不可相加为整轮耗时；不写入 SQL、账户参数或行情正文。
本批不改策略因子、分数、阈值、前端、依赖、数据库结构或调度规则。

## 验证

本地隔离相关回归 616 项通过，无失败、错误或跳过；覆盖真实计划生成与共用重验、
自动买入正常成交、最终身份变化/捕获失败、行情变化/缺失、外部错误指纹、
资金预占与成交提交、并发周期切换、运行权及架构边界。
验证入口：`python work/verify_entry_plan.py`，使用独立源码、数据和报告目录。

实际组合计划对照保留完整返回结果相等，并断言计划生成和最终重验各只计算一次行情指纹。
此前固定行情的内存副本试验中，该段 CPU 中位数约从 1.034 秒降至 0.657 秒；
这是局部隔离试验，不能推导为整轮扫描已提速 36.5%。

服务器验证继续采用禁网、无生产数据挂载的候选容器；部署前核验备份与回滚镜像，
等待自然任务释放扫描锁后切换，核对四角色版本、健康、调度和切换前后账本一致性。
新日志用于验证现场分段耗时，整轮收益需按来源、降级状态和候选数量分别评价。
