# 六步优化路线

按扫描基线 → 候选架构 → 外部等待 → 买入执行 → 自进化 → 前端推进。
每批围绕同一问题交付独立 PR；本地隔离回归、服务器隔离验证、运行身份和数据保持分别留证。
不自动合并，不通过行情降级、关闭策略通道或放宽交易门禁换取扫描耗时下降。

## 当前批次：公共输入和分时请求复用

- [x] 基线：整场同版本同日覆盖合并所有结果；耗时继续按正常、降级、失败分组。
- [x] 基线：缺少开始时间显示未知；汇总阶段调用和异常计数，明确它们不是 HTTP 请求数。
- [x] 候选：独立输入模块持有轮内可用股票/财务快照，逐策略复制，失败/空源允许恢复。
- [x] 候选：真实离线候选链路对照顺序、分数和阻断原因；保留每个策略的因子时效检查及事务内重验。
- [x] 策略分别声明评分因子；按实际模型计算所需的标准化因子，不按账户名称猜测。
  共享原始事实、硬条件、辅助排序与审计依赖保留；未声明依赖的扩展及 DSL 暂保留完整输入。
- [x] 外部等待：分时序列与微结构共用有效原始响应，原获取时间沿用到派生缓存，失败继续保持未知。
- [ ] 全量回归、服务器隔离回归、敏感内容检查、生产切换及独立 PR。

本批完成的是前三步的一组具体改进，不代表前三步所有完成标准都已满足。
真实耗时和尾部等待仍需新版本完整交易时段，冷启动按明确任务标识另列。

## 后续边界和完成标准

1. 扫描基线：正常/降级/失败/冷启动分别看中位数和 P95（95% 轮次不超过的时间）；
   样本覆盖、主机锁等待、版本和实际通道完整性均须核实。
2. 候选架构：继续以数据读取、策略计算、事务内重验为边界缩小主编排；同输入结果一致，
   再用计时、源调用和查询计数证明收益，不为拆文件增加回调层。
3. 外部等待：先检验深度/逐笔/分时复用后的实际等待，再处理概念和报价；预算须说明
   单次重试、单标的和整批并发之间的区别，不能声称现有 requests 超时是严格整批截止时间。
4. 买入执行：先提取事实读取和纯审批计算，保留最终写事务中的周期、运行权、资金、成交重验；
   验证事务缩短，并用并发换周期、重复成交和资金竞争回归守住账本。
5. 自进化：先只读核对当前可评估数据和缺口，再优化候选验证和效果归因；
   候选、已验证、待审批、已生效状态可追踪，不能把历史数据量当作当前评估能力。
6. 前端：先让用户看懂本轮慢在哪里、没有候选的原因、参数尚未生效的原因；
   再改刷新与页面整理，不将内部模块名或测试细节塞进用户流程。
