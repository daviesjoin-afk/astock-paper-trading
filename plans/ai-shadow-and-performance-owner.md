## 0. 审核后必须修正的技术判断

| 问题 | 代码证据 | 修正 |
|---|---|---|
| “版本窗口与 cycle 窗口一一对应” | `strategy_registry.bind_cycle_versions` 固定周期版本，同一版本可以绑定多个周期 | 版本与周期不是一一映射；周期还可包含多个参数覆盖时段，必须区分定义版本与实际参数身份 |
| 只读当前 `paper_nav` 就能覆盖历史 | `paper_cycle_service.archive_cycle` 保存 snapshot 后清空活动表，含 NAV；活动 NAV 只有 `(account_id, nav_date)` 唯一键 | 需要活动账本和精确周期归档读取器，不能按日期猜历史 cycle |
| “卖出额减买入额”就是已实现利润 | 买入现金流包含未平仓成本；费用及继承成本另有来源 | 把现金流和已实现盈亏分开，后者只消费既有可验证成交/成本事实 |
| 日频 NAV 能定位任意盘中参数效果 | `paper_nav` 每账户每天一行；参数可盘中追加版本 | 当天存在多套参数而无细粒度估值时，不能拆分因果收益 |
| `run_shadow_context` 参数可以直接替换 DSL 节点 | `active_runtime_checksum` 读自进化控制参数；正式三套为原生实现 | 先定义目标类型与真实消费者；调参器参数、评分权重、交易规则、DSL 分别适配 |
| 每张快照重新从固定本金起算也能比较收益 | `promotion_science._paired_excess_returns` 使用连续两张 NAV 的比值 | 两侧必须持久维护各自的现金、持仓、成本及待成交状态，不能反复重置账户 |
| UNIQUE 约束等于完整幂等 | `shadow_nav` 有 UNIQUE，另外三类明细没有相同去重合同；写入是普通 INSERT | 重复可能抛错或留下未完整控制的副作用；需要两侧原子提交与独立完成回执 |
| 影子表与正式订单分开就不影响交易性能 | 当前 `strategy_champion.ensure_schema` 及影子写入接收同一 `paper_conn` | 仍会争用 SQLite 写锁、磁盘和内存；需要短事务、隔离存储与资源租约 |
| `repeat="00:14"` 表示每 14/15 分钟运行 | `paper_schedule_contract.ScheduleTask` 的 repeat 是 Windows 调度持续时长；cron 渲染也非通用间隔解释器 | 不复制错误配置。优先事件队列；定时保底要显式表达间隔、时段和两端渲染 |

绩效 stub 与 shadow 缺少非测试外部调用者的判断在该基线成立。但“接起来就会赚”“门槛很罕见”“唯一可行路径”“零风险”都没有足够证据，不写成实施前提。

## 2. 绩效事实：先回答“数据能否支持这个数”

### 2.1 身份与边界

拟新增的 `strategy_performance.py` 至少接收：

```text
strategy_id, strategy_version, strategy_checksum
observation_start, observation_end   # 带交易所时区的 [start, end)
requested_metric_set
optional: parameter_version_id, ai_policy_fingerprint
```

读取层提供：精确 cycle pin、活动/归档来源、资本与现金变动、NAV 时点、成交与费用证明。纯计算层只接收冻结事实，不连接数据库。缺身份、歧义窗口或缺必要数据时返回具体缺口，不读 current/head/latest 猜答案。

同一策略定义版本下，因子权重、风控覆盖、组合分配、提示词或模型可不同。因此：

- **定义版本绩效**回答“这个定义在这些已知运行条件下怎样”，不是单独的 AI 增益。
- **参数时段绩效**需要参数生效前后的可验证边界估值和资金变化。
- **AI 增量效果**需要相同外部输入、独立连续状态的成对实验，不能从一条实际净值线推断。

### 2.2 活动与归档读取

1. 验证请求 checksum 与不可变版本一致，再取得该版本的全部精确周期 pin。
2. 当前活动周期读活动表；已归档周期按 `paper_archives.cycle_id` 读取对应 snapshot 和其身份，不按日期或最大的周期号拼接。
3. 每个来源记录 `archive_id / archive_format / content_fingerprint / cycle_id / source_watermark`。缺归档、损坏 JSON、缺字段及遗留 NULL stamp 各有稳定 reason。
4. 同一天启动/归档多个周期时，日频日期不足以分配记录，必须用归档边界或带时点的来源；无法唯一定位则该指标不可用。
5. 不一次解码全部历史归档放在 API 热路径。做按周期、有上限的读取和后台增量聚合，缓存键随源指纹与修订变动。
6. 读取器在只读连接上运行，不调用建表/迁移辅助函数；事实缓存写在独立研究存储，不能写回正式历史来“补齐”字段。

### 2.3 收益与现金流

原稿的两个算式必须撤回：`sell_amount - buy_amount` 不是已实现利润；`end_nav / first_daily_nav - 1` 也不天然覆盖开局第一天、现金流或切换时点。

首版输出按指标分别验证，不强行发布一个“总收益”：

| 指标 | 最低证明要求 | 缺失时 |
|---|---|---|
| 成交笔数/换手金额 | 精确策略 stamp、实际 fill、去重键、成交时间窗口 | 不把未成交订单算成交 |
| 已实现盈亏 | 对应 sell fill 的既有成本和费用证据；复用周期 owner 后再次验证 exact identity | 返回 None 与原因，不用买卖现金流替代 |
| 现金流 | 已验证的买卖支出/收入、费用和资本变动分开列示 | 名称就是现金流，不叫利润 |
| 周期净值变动 | 可定位的期初/期末估值、完整资本变动与归属 | 原始净值差可披露，但资金流不明时不发布可比较收益率 |
| 时间加权收益 | 每次外部资金流边界均有正确方向和时点的估值，可连接无现金流子区间 | 首版无法证明就不发布 TWR |
| 最大回撤 | 同一可比较净值/单位净值序列、连续覆盖、已知资金变动 | 不把每个周期最大回撤取 max 当作跨周期最大回撤 |

无外部资金变动的已验证区间，才可使用 `r = end_nav / start_nav - 1`。新周期有初始化资本快照时，首日基线应从该快照取，不能从首日收盘取而漏掉首日表现。跨资金流的子区间只有在边界估值可证明时才连接。

重置本金的独立周期默认逐周期报告，不直接连乘并称为账户真实累计收益。后续若提供合成单位指数，必须明确重新归一化、连接规则、缺口及可比身份；实际金额和合成收益分开。

跨版本持仓须读取真实 lot/成本归属与版本边界估值。NAV 本身不能证明成本继承，也不能区分旧持仓自然涨跌和新版本决策贡献。成本缺失时相应指标不可用，不能凭当前持仓或 NAV 编造成本。

### 2.4 事实对象与可信度

拟定结果结构：

```text
StrategyPerformanceFact
  owner_version, exact_identity, observation_window, scope
  status: AVAILABLE | PARTIAL | UNAVAILABLE
  metrics: {metric_name: {value, unit, status, method, reasons}}
  coverage: {expected, observed, missing, excluded, ambiguous, degraded}
  cycle_slices, source_refs, source_watermark, parameter_contexts
  quote_quality_policy_id, exclusions, blocking_reasons, fingerprint
```

全局 status 不能遮蔽逐指标状态。允许成交数可用而收益率不可用。覆盖率分母来自交易日历与应有观察区间，不是“数据库里刚好有的行数”。同一输入与同一方法指纹稳定，源更正或参数/方法变动必须改变指纹。

稳定 reason 的建议词表：`no_exact_pin / archive_missing / archive_corrupt / ambiguous_cycle_nav / missing_opening_valuation / missing_closing_valuation / unknown_capital_flow / incomplete_cost_basis / parameter_boundary_unobservable / partial_nav_coverage / degraded_quote_quality`。实现时定义一次，展示层翻译，不解析自然语言判断状态。

`quote_status` 必须使用已有状态词表及其契约，不假定只有字符串 `verified` 才有效。单源降级与已确认错误应区分；可以保留描述性数值并降低证据级别，是否允许进入晋升由独立证据政策决定。

### 2.5 接入健康/退休的次序

`strategy_health_service._performance_dimension` 当前是 stub；接新 owner 时需显式接入 `conn / identity / window` 等依赖，不能只替换一行调用。

先增加只读展示和并排对照，再允许新事实改变健康/退休输入。`UNAVAILABLE → AVAILABLE` 可能改变下游策略，即使没有直接写订单也不等于零行为风险。`signals=None` 的活动覆盖和退休阈值分别作为独立变更。

旧 `strategy_performance_owner_unavailable` 类 reason 保留供解释历史快照，但新事实必须产出具体 reason。事实可用不等于表现好，零活动不等于不健康，零收益不等于缺证据。

## 3. 影子实验：先保证比较的是会真实生效的东西

### 3.1 目标类型与消费者映射

拟定 `ExperimentTargetManifest`：`target_kind / strategy_identity / baseline_parameter_identity / allowed_fields / actual_consumer / adapter_version / required_inputs / apply_route / unsupported_reason`。

| 类型 | 回放的真实对象 | 当前能否直接复用参数 Challenger |
|---|---|---|
| selection_weights | `_candidate_rows` 消费的选股覆盖与模型族 | 不能自动等同；需原生适配器和消费证明 |
| entry_policy / exit_policy | 实际入场/持仓/退出纯决策的 policy 输入 | 需每个字段的真实接线与正反向用例 |
| allocation_overlay | 三策略分配 owner 消费的版本化声明 | 需相同组合初始状态与资金约束，不能用单账户评分代替 |
| strategy_dsl | 精确版本 AST 的合法 parameter 节点 | 仅适用于确有 DSL 的策略；未知/多余键应在适配边界拒绝 |
| tuner_controller | `self_evolution` 给 AI 调参器的步长、阈值、hold 倾向等 | 现有上下文比较的是这一类；要评估它引起的实际提案/采用链，不能伪装成股票筛选阈值 |
| code_change | 固定代码提交、配置与依赖形成的候选产物 | 隔离构建和回放；不在运行进程里执行模型自由生成的代码 |

首个交付只选一个原生策略的实际权重消费者；能运行的范围比把三个策略都标记“已支持”更重要。相同模型族并不等于相同策略身份。旧两套保留历史解释能力，但不进入新实验的正式参与者集合。

**消费证明**：用一个专门构造的敏感样本，让合法参数变更确实改变目标函数输入/输出；再用生产回放样本对照正式计算。随机样本结果相同既不能证明没接线，也不能证明有接线。

### 3.2 共同环境与各自状态

共同冻结的外部环境包括：证券集合、市场/行情/可交易性/因子指纹、数据可用时间、交易规则版本、费用/滑点/容量规则、决策时刻。初始现金和持仓种子相同，两侧后续状态允许分化。

```text
共同环境 E_t
Champion:  S_c,t + P_c + E_t → 决策 → 既有模拟执行原语 → S_c,t+1 → NAV_c,t+1
Challenger: S_x,t + P_x + E_t → 决策 → 既有模拟执行原语 → S_x,t+1 → NAV_x,t+1
```

`S` 至少包括现金、持仓 lots、可卖日期、成本、待成交意图、未完成委托、风险状态、费用、已消费事件与状态水位。每轮保存独立状态和校验和，下一轮从各自已提交状态继续。不能两边每轮都读正式持仓，也不能每轮归零重算。

共同 `environment_hash` 用于配对；两侧的参数和状态哈希单独记录。不能把分化后的角色状态塞进共同环境指纹，导致两侧无法配对。

复用现有选股/决策/执行原语。`execution_planner` 的价格、门禁和执行估算原语只是组件，还需完整驱动持仓、费用与 NAV 的状态转移；不复制第二套撮合，也不调用正式账本写入接口。

### 3.3 点时数据和历史可做范围

PIT（点时数据）是“当时已经可用”，不只是报表上写着过去日期。输入包要保存 `event_time / available_at / ingested_at / decision_at`、证券集合时点、披露时间、行情质量与交易状态。

- 不用今天的证券集合、后来披露的财务字段、修订后的缺省行情反填过去。
- 只有日线时不能宣称已验证竞价或分钟级时机；没有历史盘口时，给出支持的成交假设与敏感性边界。
- 未来价格只供成熟标签评估，不能出现在当时的模型上下文或候选特征中。
- 历史回放须记录 `evidence_origin=historical_replay`；实时影子为 `live_shadow`。两者不因输出格式相同而共享“新鲜交易日数”。

### 3.4 时间、样本与晋升

当前 `promotion_science` 从 `shadow_nav.created_at` 派生 evidence_day。实时采集和历史重放共用这条语义之前，必须补来源和时间校验：**严禁把重放历史日期传入 observed_at 来凑满五天**。

既有路径要求 ≥12 配对快照、≥10 区间、≥5 不同天、末段 holdout（样本外保留段）及对应置信和胜率门槛；`evaluate_challenger` 还先检查至少一小时的提案后观察窗。这些是当前检查逻辑，不是完成系统后一定晋升的承诺。

实时证据由平台可信时钟和市场日历生成，时间单调、无未来事件、无跨休市污染。同一天多拍快照不会增加不同交易日；外部环境没变时也不通过随机 nonce 制造“新样本”。初始五天不足仍须等待，但同时可以运行历史实验、机械校验和别的候选研究。

同日区间相关，`mean - 1.96 * stderr` 的现有算法不能自动等同于充分处理了相关性、多候选搜索与重复看结果。先报告这些限制，新增科学政策另做版本化验证；不能静默放松现有常量。

## 4. 存储、幂等与任务调度

### 4.1 隔离存储和事务

优先把研究队列、运行状态、回放明细和汇总放入独立实验存储；正式账本由只读适配器提供冻结输入。数据库具体名称沿用现有数据路径规范，先检查能否复用已有研究存储。

fencing token 是每次领取任务时递增的租约代号：新任务接管后，旧进程拿旧代号写入就会被拒绝，防止超时任务“复活”覆盖新结果。

现有 `strategy_champion` 把 schema 初始化、状态读取、比较与写入绑在一起。迁移到实验存储需要拆适配器，不能简单把 `paper_conn` 换成空数据库就宣称隔离完成。正式参数采用仍走原唯一写入者及整体方案的授权凭据流程。

拟定事务回执键：

```text
(experiment_id, target_identity, environment_hash, transition_sequence, evaluator_version)
```

一次原子提交包括：两侧明细、两侧后继状态、NAV、输入/输出哈希和完成回执。重复请求读取同一回执；B 侧失败则 A 侧也不发布完成结果。不可只 catch `IntegrityError` 后宣称整批成功。

两个数据库之间不假定存在跨库事务。采用请求使用 outbox（持久待办记录）及幂等回执；超时后按已提交事实重试或补偿，不把“消息发出”当成“已生效”。陈旧 fencing token、版本变化和已撤销授权必须在写前拒绝。

### 4.2 持久 worker 与定时保底

主要驱动是提交后的事件：新快照、候选落库、输入可用、标签成熟、上步完成、授权撤销。沿用已有 dispatch/资源租约思路，为每策略串行推进状态；低优先级回放与模型调用分开限额。

保底定时任务只投递未处理事件和检查卡住的租约，不对每个候选重复全量回算。先试单 worker、单重型回放；盘中有限额，盘后再提高额度，依据实测容量决定。

如仍需 `shadow-run` runner-only 入口，应一次修改完整合同：

1. runner-only 词表、实际分派、交易日/交易时段与结果退出码。
2. 明确的 interval 和 Windows/Linux 渲染；`repeat` 原字段是持续时长，不拿来偷表达间隔。
3. 调度文件、安装程序、资源锁、重试上限、只读健康状态和对应合同测试。
4. 不经交易 `run_slot` 写路径，但仍受数据、资源和观察身份检查。

不硬编码“09:41 后每 15 分钟”并忽略午休、开盘拥挤和超时跨时段。若平台支持按变化投递，应优先复用，避免为凑证据机械拍照。

### 4.3 状态和重试

| 结果 | 队列动作 | 证据含义 |
|---|---|---|
| no_challenger / already_done | 合法跳过 | 无新实验事实 |
| waiting_data / waiting_label | 等待新水位或标签事件 | 不当作计算故障重试 |
| stale_base / expired | 终止旧任务，按需生成新上下文 | 不能混接旧实验状态 |
| deferred_resource / provider_timeout | 有上限的延迟重试 | 不修改结果与证据来源 |
| failed | 保存失败步骤、部分工作和回滚状态 | 未完成不算通过 |
| completed | 回执完整、两侧状态已提交 | 只表示实验执行完成，不表示候选胜出 |

不能为了 `_result_exit_code` 返回 0 而把部分失败改名 completed。CLI 的成功、可重试和终止失败映射必须和调度合同一起设计并测试。

## 5. 速度与资源的验收

每阶段记录 `queue_wait / snapshot_read / archive_decode / feature_build / provider_wait / evaluator_cpu / sqlite_lock_wait / persist / admission_wait`。LLM 的等待与本地计算分开，模型返回慢时不盲目加 worker。

- 输入和方法均相同时复用结果；缓存键至少含精确身份、参数、数据水位、规则与适配器版本。
- 明细增量写入，统计按完成的 transition 更新；API 读预聚合结果，不扫描全归档。
- 提供未完成原因和覆盖率，即使没达到科学晋升门槛也必须能及时反馈“接线正确/结果更差/缺何种证据”。
- 冷缓存、热缓存、数据降级各分组压测；同日人工运行的少量样本不能证明稳定提速。
- 盘中试运行前，确定 CPU/内存/磁盘/调用费用上限和交易扫描 p95 可接受退化预算。当前服务器容量必须现场测量，不沿用旧报告的可用空间。
- 磁盘配额优先保留实验 manifest、结果、失败记录与引用；明细压缩/清理不删除晋升与追溯依赖的事实。保留策略先版本化，再让 Agent 消费它。

## 6. 分批交付与停止条件

| 切片 | 最小成果 | 放行到下一步的条件 |
|---|---|---|
| F0 事实样本与测量 | 当前三套的身份、归档与参数消费者清单；各阶段计时 | 每项缺口有可复现原因，未支持内容标记明确 |
| F1 首个原生实验 | 一种真实权重覆盖 + 一个合格冻结历史窗口 + 连续双账户回放 | 参数消费证明、确定性、成本和资金守恒成立 |
| F2 绩效 owner | 活动/归档读取、逐指标状态、资本流与参数边界 | 缺数据不造数，历史账本无写入 |
| F3 持续增量 | 队列接续、幂等回执、状态恢复、实时影子采集 | 不争抢交易热路径；重启、重复事件与B侧失败安全 |
| F4 采用接口 | 精确证据引用、现有晋升链适配、范围授权消费者 | 科学通过、授权通过、写前复核三者分别可核验 |

F1 和 F2 可并行开发；允许跑机械实验不等于允许作收益结论。缺完整分钟/披露历史时，先交付受限的可运行范围和补采任务，不承诺虚构的回测覆盖。工作量按上述端到端样本实际完成度估算，撤回原稿预先给定的行数与人日保证。

上线顺序：临时目录离线回放 → 无生产数据的镜像验证 → 服务器只读输入与隔离实验 → 限额实时影子 → 单独审批正式消费能力。任何一步失败，保留任务/事实，停用新增工作；不删除历史、复原已成交或自动重置正式周期。

## 7. 必须覆盖的验证矩阵

绩效读取：

- [ ] 无 exact pin 不回落 current head；checksum 不符和身份冲突被拒绝。
- [ ] 一版本多周期、同日多个周期、活动与归档混合读取，来源可唯一定位。
- [ ] 归档缺失/损坏/旧字段不全逐项显式降级；重复来源不重复计算。
- [ ] 首日基线、结束边界、资本重配与现金流处理正确；缺关键边界不发布收益率。
- [ ] 买入未平仓不会变成已实现亏损；成本/费用缺失不被填零。
- [ ] 日内参数变化无法由日频 NAV 分开时，参数级绩效诚实不可用。
- [ ] 跨周期回撤不以周期内回撤最大值替代；独立重置本金不冒称真实复利。
- [ ] 两个有效平净值时点可以得到零收益；一个时点不够则仍是样本不足。
- [ ] 降级行情与错误行情分开；覆盖率分子、分母及排除项一致。
- [ ] 只读连接、无 schema 初始化/写 SQL、同输入指纹稳定、源更正后失效。

实验与接线：

- [ ] 三套原生策略不会误走空 DSL；调参器控制参数不冒充实际选股参数。
- [ ] 允许字段有真实消费者与敏感用例；未知字段/类型拒绝，不静默忽略。
- [ ] 相同初始状态与外部输入下，未改参数的两侧一致；参数改变时能解释差异。
- [ ] 连续现金、持仓、费用和 T+1 状态正确，重复批次不重置本金。
- [ ] 一侧失败、重复任务、乱序事件、重启和陈旧租约均不会重复发布结果。
- [ ] 历史重放、实时采集、事件时间和写入时间不可互相冒充；不能回填日期凑晋升。
- [ ] 点时证券集合、披露时间、未来标签、费用、停牌、无法成交和缺分钟数据均有负向用例。
- [ ] 参数头或代码基线变化使旧上下文失效；候选身份不能漂移到最新版本。
- [ ] 纯计算不调网络/模型、不读 current head、不写库；编排和持久化职责单独测试。
- [ ] 完整比较的证据政策重新校验，预注册与 LLM 评价不能生成 winner 权威。

运行与采用：

- [ ] 正式账本在离线/影子运行期间无实验写入；在线自然交易需按 writer 来源区分，不能只比较表行数。
- [ ] 明细、状态、NAV 和完成回执原子发布；跨库超时可从真实回执恢复。
- [ ] 队列拥堵、模型超时、低磁盘、SQLite 锁等待均有明确终态和限额重试。
- [ ] 三套启用范围、初始预算和历史只读身份保持；旧两套不被重新启用。
- [ ] 调度词表、时段、实际间隔、Windows/Linux 渲染、退出码和部署文件一致。
- [ ] 未授权或证据不足时仅留候选；授权撤销后不能由旧任务继续采用。
- [ ] 观察期降级和参数回退不被描述为撤销已成交；资金守恒与保护性退出仍由原 owner 验证。

测试以小型人工可核算账本、冻结黄金样本和实际消费者为主。不能靠给假 runner 返回“更高 NAV”、改 created_at 或降低门槛，让验收看起来全绿。
