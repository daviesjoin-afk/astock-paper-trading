## 3. 变更内容：四批

### 3.1 账本连接归 `paper_storage`

`paper_trading._db` / `_db_readonly` / `_evolution_conn` 与 `adaptive_engine._connect` 一直是外部拿数据库连接的唯一途径，其中 10 个模块（`api_paper`、`api_settings`、`main`、`push_report` 与四个 `strategy_*_service`）为了**一条连接**去 import 交易主引擎。

公开面改为 `paper_storage.paper_db()` / `paper_db_readonly()` / `evolution_connection()` / `paper_db_path()` / `adaptive_db_path()` / `bind_ledger_path()`。连接参数（1s/120s 超时、800ms/60000ms busy_timeout、WAL、foreign_keys、query_only）逐字未改。14 个模块、27 个访问点改调公开面。

账本路径用 `bind_ledger_path(lambda: DB_PATH)` 晚绑定：本仓 88 处测试用 `P.DB_PATH = <临时库>` 指向临时库，公开入口必须跟随它，否则测试会写到真实账本。

### 3.2 76 个跨模块私有 helper 提为公开名

每个 owner 末尾保留一行 `<private> = <public>` 别名。9 个目标与局部变量撞名，改用不撞名的公开名：`query_rows`、`resolve_strategy_stamp`、`load_active_cycle`、`current_selection`、`account_conditions`、`rule_constraints`、`load_account_params`、`build_scenario_sessions`、`parse_shadow_instant`。

### 3.3 `init_db` 409 行 → 28 行

231 行建表 DDL、55 行迁移与历史行修补、21 个逐特性 `ensure_*` 全部下沉到 `paper_schema_migrations`（`CORE_TABLES_DDL` / `ensure_core_tables` / `ensure_current` / `ensure_feature_tables`）。三个业务常量由调用方传入，schema owner 不反向依赖引擎。

**顺带修掉一个真实缺陷**：快速路径与完整路径原来各维护一份升级链，且已经漂移（快速路径有 `ensure_rebalance_state_cycle_ownership`，完整路径没有）。这正是历史上"升级后的库缺新表、第一次写入 `no such table`"反复出现的根因。现在两条路径共用 `_upgrade_ledger`，不可能再漂移。

### 3.4 刻意**不**公开的一个

`ai_research_contract._issue_evidence_ref` 保持私有。它的私有性本身是强制机制：`ResearchEvidenceRef` 没有公开裸构造器，5 条架构守卫（`EVIDENCE-03`、`NEWS_25`、`INC_29`、`INC_30`、`FINAL_G08`）用 `(模块, enclosing function)` 精确 allowlist 保证契约外零签发。公开它等于把**强制**降级为**约定**。这一条是审计建议被测试推翻的例子（原建议见审计报告 §3 的 P4）。

## 7. 运维须知

### 7.1 回滚

代码回滚（不改数据）：

```bash
cd /opt/astock-codex
sudo git reset --hard ee9e604
sudo bash deploy/deploy.sh --no-migrate
```

数据回滚（仅在确认账本被写坏时）：

先挑备份目录，再显式确认恢复。`restore.sh` **必须**带 `--confirm-restore` 和备份目录两个参数，否则直接以退出码 2 结束：

```bash
# 1) 挑备份目录（本次部署前留档 + 日常 20:10 备份都在这里）
sudo ls -1dt /var/backups/astock-codex/daily/*/ | head

# 2) 显式确认恢复；目录必须含 SHA256SUMS，脚本会先校验再停服务、逐库 integrity_check
cd /opt/astock-codex
sudo bash deploy/restore.sh --confirm-restore /var/backups/astock-codex/daily/20261029-2019
```

`restore.sh` 的行为顺序（不要试图绕过）：校验 `SHA256SUMS` → 解压到临时目录 → 每个库 `PRAGMA integrity_check` → 停容器 → 替换 → 起容器。目录里没有 `SHA256SUMS`、或任一库完整性检查不通过时，它会在停服务**之前**退出。

本次迁移是幂等建表 + 列升级（`CREATE ... IF NOT EXISTS`），**没有**版本号推进，也没有回填或删行，因此 `--no-migrate` 回滚不会留下不兼容的 schema。
